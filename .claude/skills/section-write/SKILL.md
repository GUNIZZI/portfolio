# section-write

**이 스킬에는 규칙을 적지 않는다.** 절차만 적는다.
구조는 `docs/architecture.md`, 이름은 `docs/conventions.md`, 색은 `docs/theme.md`, 모션은 `docs/motion.md` 를 따른다.

## 1. 읽는다

위 네 문서를 읽는다. 요약하지 않는다.
같은 섹션이 이미 있으면 `src/features/<섹션>/` 전체를 읽는다.

## 2. 설계를 한 번에 보고한다

코드를 쓰기 전에 아래를 표 하나로 내밀고 승인받는다. Plan 모드에서 받았다면 다시 묻지 않는다.

| 항목            | 내용                                                      |
| --------------- | --------------------------------------------------------- |
| 슬라이스        | `src/features/<camelCase>/` — 파일 목록                   |
| 데이터          | 어느 entity 의 `~Data` 를 받는가. 없으면 `config/` 상수   |
| 서버/클라이언트 | `'use client'` 를 붙일 가장 작은 컴포넌트                 |
| 모션            | 요소마다 도구(framer-motion / GSAP / CSS) · 토큰 · 트리거 |
| 동작 줄이기     | 동작 줄이기에서 보일 최종 상태                            |

## 3. 만든다

```
src/features/<섹션>/
├── index.ts                  ui 만 공개
├── ui/<Section>.tsx          서버 컴포넌트. 마크업과 글자
├── ui/<Section><Part>.tsx    'use client'. 움직이는 부분만
└── model/<섹션>.motions.ts   variants · 타임라인 구성
```

- 새 원자 컴포넌트가 필요하면 먼저 `src/shared/ui/` 에 있는지 본다. 없으면 이 슬라이스 `ui/` 에 두고,
  2번째 사용처가 생길 때 올린다.(architecture.md 원칙 2)
- 훅(`guard_tokens.py`)이 걸면 고친다. 그대로 둘 근거가 있으면 주석으로 남긴다.

## 4. 확인한다

1. `pnpm check` 를 통과시킨다.
2. Playwright MCP 로 `pnpm dev` 화면을 띄워 섹션까지 스크롤하고 스크린샷을 찍는다. 데스크톱과 모바일 폭 둘 다.
3. 동작 줄이기를 켠 상태로 다시 본다. 최종 상태가 보이고 아무것도 움직이지 않아야 한다.
4. `motion-a11y-check` 에이전트에 이번에 만든 파일 목록을 넘긴다.

## 5. 보고한다

만든 파일, 모션 설계표, 스크린샷 경로, 에이전트가 짚은 것과 처리 결과를 보고한다.
커밋은 하지 않는다. `/commit` 또는 `/commit-quick` 을 호출하라고 안내한다.
