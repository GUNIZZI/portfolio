# 홈 (`/`) — 기획

사이트의 첫 화면이다. GUNI 를 소개하고, 작업 보기와 연락으로 이어 준다.

이 문서는 **이미 있는 페이지에 새 동작을 더하는 기획**이다.(`../README.md` 3.1)
섹션 구성 · 문구 · 배치는 코드에 있고 디자인 원본(`sample/HYOSUNG 포트폴리오.html`)과 같다. 표시 없이 적는다.
외부 링크 · 모션 · 상태는 기획안으로 채웠고, 사용자가 모두 채택했다.(요구사항 7)
채택한 동작은 모두 구현했다. 남은 결정은 [검토 필요 사항](#검토-필요-사항)에 있다.

## 요구사항

사용자가 정한 요구사항이다.

1. **디자인은 `sample/HYOSUNG 포트폴리오.html` 을 따른다.**(2026-11-12)
2. **이름은 GUNI 로 쓴다.**(2026-11-12)
3. **연락 메일은 `h2dlhs@naver.com` 이다.**(2026-11-12)
4. **블로그와 유튜브 링크는 두지 않는다.**(2026-11-12)
5. **인터랙션과 모션은 정적 화면을 맞춘 다음 단계에서 붙인다.**(2026-11-11)
6. **이력서 내려받기는 두지 않는다.** 이력서에 연락처가 들어가 공개할 수 없다.(2026-11-12)
7. **이 문서에 `제안` 으로 적었던 기획안을 모두 채택한다.**(2026-11-12)
   현재 메뉴 표시 · 헤더 고정 · 외부 프로필 새 탭 · 모션 전체 · 히어로 이미지 최적화 · 성능 목표다.
8. **LinkedIn 링크는 두지 않는다.** 계정이 없다.(2026-11-12)
9. **모바일에서는 헤더 메뉴를 햄버거 메뉴로 연다.**(2026-11-12)
10. **기술 아이콘이 흔들리는 시간은 `duration-base` 다.** `duration-fast` 는 짧았다.(2026-11-12)
11. **모바일 메뉴의 기획안을 모두 채택한다. 패널은 화면 전체를 덮지 않는다.**(2026-11-12)
12. **헤더는 처음부터 화면 위에 고정한다.** 히어로를 지난 뒤에 내려오는 방식은 쓰지 않는다.(2026-11-12)
13. **헤더 메뉴는 페이지로 연결한다.** Home · Projects · About 이고 Skills 는 뺀다.(2026-11-16)
14. **모바일 메뉴 패널은 화면 전체를 덮는다.** 11번의 "덮지 않는다" 를 바꿨다.(2026-11-19)

## 정책

### 섹션 구성

코드에 있는 순서다.(`src/app/(site)/page.tsx`)

| 순서 | 섹션      | id         | 담당                        |
| ---- | --------- | ---------- | --------------------------- |
| 1    | 헤더      | —          | `widgets/header`            |
| 2    | 히어로    | —          | `features/hero`             |
| 3    | 대표 작업 | `projects` | `features/featuredProjects` |
| 4    | 기술      | `skills`   | `features/skills`           |
| 5    | 소개      | `about`    | `features/about`            |
| 6    | 연락      | `contact`  | `widgets/contact`           |
| 7    | 푸터      | —          | `widgets/footer`            |

페이지 맨 위는 `#top` 이다. 홈에서는 로고와 헤더의 Home 이 이곳을 가리킨다.

### 메뉴

- **헤더 메뉴는 Home · Projects · About 이고, 메뉴 하나가 페이지 하나다.**(2026-11-16 사용자 결정, `src/config/nav.ts`)
    - Home 은 `/`, Projects 는 `/work`, About 은 `/about` 이다.
    - 처음에는 홈 안의 섹션으로 가는 메뉴 4개였다. 소개 페이지가 생기면서 About 을 눌러도 그 페이지에 가지 못해 바꿨다.
    - Skills 는 메뉴에서 뺐다. 기술 전용 페이지가 없고, 홈과 소개 페이지에 섹션으로 들어 있다.
- 연락 섹션으로는 헤더 오른쪽의 Contact 버튼으로 간다. 메뉴에는 Contact 를 두지 않는다.(2026-11-12 사용자 결정)
    - **연락 섹션은 모든 페이지의 푸터 위에 있다.**(2026-11-16 사용자 결정) Contact 는 어느 페이지에서든 그 페이지의 연락 섹션(`#contact`)으로 간다.
    - 404 와 에러 화면에는 연락 섹션을 두지 않는다.(2026-11-20 사용자 결정, `src/app/(site)/not-found.tsx` · `error.tsx`)
    - 모든 페이지에 붙는 것이라 feature 가 아니라 위젯이다.(`src/widgets/contact/`, `docs/architecture.md` 3.1)
- 푸터 메뉴는 Home · Projects · About · Contact 다. 앞의 3개는 헤더와 같은 페이지로 간다.
- **현재 메뉴 표시**: 지금 있는 페이지의 메뉴에 밑줄과 강조색을 준다.(`src/widgets/header/HeaderBar.tsx`)
    - **밑줄은 하나다.** 메뉴를 옮기면 그 메뉴로 미끄러져 가고, 폭도 그 메뉴의 글자에 맞춰진다.(2026-11-18 사용자 결정, `src/shared/ui/navIndicator/NavIndicator.tsx`)
    - 헤더는 페이지가 아니라 레이아웃이 그린다. 페이지를 옮겨도 헤더는 남고 그 아래만 바뀐다.(2026-11-18 사용자 결정, `src/app/(site)/layout.tsx`)
    - 어느 메뉴인지는 헤더가 주소에서 읽는다. 작업 상세(`/work/<id>`)도 Projects 를 강조한다.(`src/config/nav.ts` 의 `findNavHref`)
    - 주소를 읽는 헤더는 `<Suspense>` 안에 둔다. 밖에 두면 미리 그려 두지 않은 작업 상세의 틀을 만들지 못해 빌드가 실패한다.(`src/app/(site)/layout.tsx`)
    - 메뉴의 주소에 이미 있을 때 그 메뉴를 누르면 페이지를 다시 불러오지 않고 맨 위로 올라간다.
    - 작업 상세에서 Projects 를 누르면 목록(`/work`)의 맨 위로 간다. 강조된 메뉴여도 주소가 다르면 그 메뉴의 페이지로 옮긴다.(2026-11-20 사용자 결정, `src/widgets/header/NavLink.tsx`)
    - 처음에는 스크롤에 따라 보고 있는 섹션의 메뉴를 강조했다. 메뉴가 페이지를 가리키게 되면서 없앴다.
- 홈 안의 섹션으로 가는 길은 히어로의 View My Projects(`#projects`)와 Contact 버튼(`#contact`)이 남는다.
- **헤더 고정**: 헤더는 처음부터 화면 위에 붙어 있다.(요구사항 12, `src/widgets/header/HeaderBar.tsx`)
    - 맨 위에서는 바탕이 없고, 스크롤을 시작하면 바탕을 반투명으로 흐린다.
    - 버튼으로 섹션에 갈 때는 헤더 높이만큼 덜 올라가 제목이 헤더에 가리지 않는다.(`src/style/tokens/layout.css` 의 `scroll-mt-header`)

### 테마

- **테마는 다크와 라이트 2개이고, 헤더의 테마 버튼으로 바꾼다.**(2026-11-18 사용자 결정, `src/shared/ui/themeToggle/ThemeToggle.tsx`)
    - 버튼은 Contact 버튼의 오른쪽에 있다. 다크에서는 해, 라이트에서는 달 아이콘이다.(2026-11-18 사용자 결정, `src/widgets/header/HeaderBar.tsx`)
    - 1280px 이상에서는 테마 버튼과 관리 버튼이 본문 폭 바깥으로 나가고, Contact 버튼이 본문의 오른쪽 끝에 맞는다. Tailwind 의 `xl` 경계다.
    - 테마 버튼의 오른쪽에 관리 화면(`/admin`)으로 가는 자물쇠 버튼이 있다.(2026-11-18 사용자 결정) 새 탭에서 연다.(2026-11-24 사용자 결정, `src/widgets/header/HeaderBar.tsx`)
    - 모든 공개 페이지의 헤더에 있다. 관리 화면의 버튼은 [대시보드 기획](../admin/dashboard/README.md) 「GNB」 에 있다.
- **처음 방문은 다크다.** OS 의 설정을 따르지 않는다.(2026-11-18 사용자 결정, `src/_app/Providers.tsx`)
- 바꾼 테마는 브라우저에 저장해 다음 방문과 다른 페이지에서도 유지한다. 공개 화면과 관리 화면이 같은 값을 쓴다.
- 색 값은 `docs/theme.md` 1.2절과 `docs/design.md` 1.1절에 있다.

### 모바일 메뉴

요구사항 9번이다. 아래 기획안을 사용자가 모두 채택했다.(요구사항 11) 패널의 크기는 요구사항 14 로 바꿨다. 구현은 `src/widgets/header/HeaderBar.tsx` 에 있다.

- **전환 폭**: 768px 미만에서 햄버거 메뉴로 바꾼다. Tailwind 의 `md` 경계다.
- **좁은 화면의 헤더**: 로고와 테마 버튼 · 관리 버튼 · 메뉴 버튼만 한 줄에 둔다. 메뉴 3개와 Contact 버튼은 패널로 옮긴다.
- **패널**: 메뉴 버튼을 누르면 헤더 바로 아래에서 화면 끝까지 덮는다.(요구사항 14, `src/style/tokens/layout.css` 의 `h-below-header`) 메뉴 3개를 세로로 놓고 그 아래에 Contact 버튼을 둔다.
    - 바탕은 헤더와 같은 `glass` 다. 층은 `z-overlay` 다.(`docs/theme.md` 3절)
        - 패널이 열려 있는 동안에는 맨 위에서도 헤더에 `glass` 바탕과 흐림을 준다. 헤더만 비어 있으면 패널과 끊겨 보인다.(2026-11-19 사용자 결정, `src/widgets/header/HeaderBar.tsx`)
        - 뒤의 화면은 반투명 바탕 너머로 흐리게 비친다. 스크롤은 잠그지 않는다.
        - 내용이 화면보다 길면 패널 안에서 스크롤한다.
- **닫기**: 메뉴 버튼을 다시 누름 · 항목을 누름 · `Esc`. 패널이 화면을 다 덮어 밖을 눌러 닫는 방법은 없다. 화면이 768px 이상으로 넓어져도 닫힌다.
    - 메뉴 항목을 누르면 패널을 닫고 그 페이지로 간다.
    - Contact 처럼 같은 페이지의 섹션으로 가는 링크는 패널이 다 닫힌 뒤에 이동한다. 누른 항목이 이동 도중에 사라지면 브라우저가 스크롤을 멈춘다.
- **현재 메뉴 표시**: 패널의 항목에도 지금 있는 페이지를 강조색으로 표시한다.
- **아이콘**: 메뉴 버튼은 닫혀 있을 때 줄 3개, 열려 있을 때 ✕ 다. `shared/ui/icon` 의 `menu` · `close` 다.

### 링크 연결

다른 페이지로 가는 링크다.

| 요소              | 목적지       | 근거                                                    |
| ----------------- | ------------ | ------------------------------------------------------- |
| View All Projects | `/work`      | `src/features/featuredProjects/ui/FeaturedProjects.tsx` |
| 작업 카드         | `/work/<id>` | `src/entities/project/services/project.services.ts`     |
| More About Me     | `/about`     | `src/features/about/ui/About.tsx`                       |

- **작업 카드는 어디를 눌러도 상세로 간다.**(2026-11-16 사용자 결정) 처음에는 열기 아이콘만 링크였다.
    - 링크는 하나이고, 누를 수 있는 면만 카드 전체로 넓혔다. 스크린 리더는 「<작업 이름> 열기」 로 읽는다.(`src/features/featuredProjects/ui/ProjectCard.tsx`)
- 작업 원문에 `href` 가 있으면 카드는 그 주소로 간다.
- 카드 주소의 `id` 는 저장소가 발급한 `id` 다.([admin/](../admin/README.md) 요구사항 10)
- **대표 작업에는 관리 화면에서 홈 노출을 켠 작업만 나온다.** 공개한 작업 전체는 작업 목록(`/work`)에 있다.([admin/](../admin/README.md) 요구사항 26, `src/entities/project/services/project.services.ts` 의 `getFeaturedProjectList`)
- 홈 노출을 켠 작업이 없으면 섹션을 그대로 두고, 카드 대신 「아직 등록된 프로젝트가 없습니다」 를 보여 준다.([admin/](../admin/README.md) 「공개 화면 반영」, `src/features/featuredProjects/ui/FeaturedProjects.tsx`)
- 소개 페이지와 작업 목록 · 상세를 만들었다.([about/](../about/README.md) · [work/](../work/README.md)) 작업 상세의 본문은 아직 임시 문구다.

**GitHub 는 프로필 주소(`https://github.com/GUNIZZI`)로 새 탭에서 연다.**(2026-11-16 사용자 결정, `src/config/site.ts`)
LinkedIn 은 두지 않는다.(요구사항 8)
`http` 로 시작하는 주소에는 `target="_blank"` 와 `rel="noopener noreferrer"` 를 붙인다.(`src/widgets/footer/Footer.tsx`)

### 이메일

- 연락 버튼은 `Get in Touch` 1개다. 메일 주소 버튼은 따로 두지 않는다.(2026-11-12 사용자 결정)
- 버튼에 마우스를 올리거나 키보드로 초점을 주면 문구가 메일 주소로 바뀐다. 버튼 폭은 변하지 않는다.(`src/widgets/contact/Contact.tsx`)
- 터치 화면에서는 문구가 바뀌지 않는다. 마우스 오버가 없기 때문이다.
- 누르면 `mailto:` 로 메일 앱을 연다.
- 메일 주소 복사와 복사됨 토스트는 두지 않는다. 채택했다가, 메일 주소 버튼을 없애면서 함께 뺐다.(2026-11-12 사용자 결정)

### 임시 값

- 소개 섹션의 숫자 3개는 원본 값이다. 사용자가 관리 화면의 소개에서 바꾼다.([소개 관리 기획](../admin/about/README.md))
- 썸네일이 없는 작업 카드는 임시 이미지를 표시한다. 지금은 4번째 작업이다.(`src/features/featuredProjects/ui/ProjectCard.tsx`)

    - 완성된 테두리를 둥근 마스크로 가려 두고, 마스크의 가운데를 포인터에 맞춘다. 가운데가 가장 밝고 바깥으로 갈수록 옅어진다. 불빛의 반지름은 192px 이다.(`src/features/featuredProjects/model/useCardSpotlight.ts`)

## 접근성 · 성능 고려

- 손글씨 장식 문구(말풍선, `Ideas Design…`, `Let's Build…`, `Good Ideas…`)는 `aria-hidden` 이다. 같은 뜻이 본문에 있다.
- 아이콘만 있는 링크(작업 열기, 외부 프로필)에는 `aria-label` 이 있다.
- 히어로 이미지는 WebP 다(85KB). 화면 폭에 맞는 크기는 `next/image` 가 내려 준다.(`src/features/hero/ui/HeroVisual.tsx`)
- 세어 올라가는 숫자는 스크린 리더에 최종 값만 읽어 준다.(`src/features/about/ui/CountUp.tsx`)
- 모바일 메뉴 버튼은 `aria-expanded` 와 `aria-controls` 를 갖고, 이름은 「메뉴 열기」 · 「메뉴 닫기」 로 바뀐다. 크기는 44px 이상이다.
- 모바일 메뉴를 `Esc` 로 닫으면 초점이 메뉴 버튼으로 돌아간다. 닫힌 패널은 초점을 받지 않는다.
- 등장 연출이 레이아웃을 밀지 않게 한다. 목표는 CLS 0, Lighthouse 성능 90 이상이다. Lighthouse 는 아직 재지 않았다.
