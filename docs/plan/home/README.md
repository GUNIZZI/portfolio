# 홈 (`/`) — 기획

사이트의 첫 화면이다. GUNI 를 소개하고, 작업 보기와 연락으로 이어 준다.

이 문서는 **이미 있는 페이지에 새 동작을 더하는 기획**이다.(`../README.md` 3.1)
섹션 구성 · 문구 · 배치는 코드에 있고 디자인 원본(`sample/HYOSUNG 포트폴리오.html`)과 같다. 표시 없이 적는다.
외부 링크 · 모션 · 상태는 기획안으로 채웠고, 사용자가 모두 채택했다.(요구사항 7)
채택한 동작은 모두 구현했다. 남은 결정은 [검토 필요 사항](#검토-필요-사항)에 있다.

## 요구사항

사용자가 정한 요구사항이다.

1. **디자인은 `sample/HYOSUNG 포트폴리오.html` 을 따른다.**(2026-11-12)
2. **이름은 GUNI 로 쓴다.**(2026-11-12)
3. **연락 메일은 `h2dlhs@naver.com` 이다.**(2026-11-12)
4. **블로그와 유튜브 링크는 두지 않는다.**(2026-11-12)
5. **인터랙션과 모션은 정적 화면을 맞춘 다음 단계에서 붙인다.**(2026-11-11)
6. **이력서 내려받기는 두지 않는다.** 이력서에 연락처가 들어가 공개할 수 없다.(2026-11-12)
7. **이 문서에 `제안` 으로 적었던 기획안을 모두 채택한다.**(2026-11-12)
   현재 메뉴 표시 · 헤더 고정 · 외부 프로필 새 탭 · 모션 전체 · 히어로 이미지 최적화 · 성능 목표다.
8. **LinkedIn 링크는 두지 않는다.** 계정이 없다.(2026-11-12)
9. **모바일에서는 헤더 메뉴를 햄버거 메뉴로 연다.**(2026-11-12)
10. **기술 아이콘이 흔들리는 시간은 `duration-base` 다.** `duration-fast` 는 짧았다.(2026-11-12)
11. **모바일 메뉴의 기획안을 모두 채택한다. 패널은 화면 전체를 덮지 않는다.**(2026-11-12)
12. **헤더는 처음부터 화면 위에 고정한다.** 히어로를 지난 뒤에 내려오는 방식은 쓰지 않는다.(2026-11-12)

## 정책

### 섹션 구성

코드에 있는 순서다.(`src/app/page.tsx`)

| 순서 | 섹션      | id         | 담당                        |
| ---- | --------- | ---------- | --------------------------- |
| 1    | 헤더      | —          | `widgets/header`            |
| 2    | 히어로    | —          | `features/hero`             |
| 3    | 대표 작업 | `projects` | `features/featuredProjects` |
| 4    | 기술      | `skills`   | `features/skills`           |
| 5    | 소개      | `about`    | `features/about`            |
| 6    | 연락      | `contact`  | `features/contact`          |
| 7    | 푸터      | —          | `widgets/footer`            |

페이지 맨 위는 `#top` 이다. 로고와 헤더의 Home 이 이곳을 가리킨다.

### 메뉴

- 헤더 메뉴는 Home · About · Projects · Skills 다. 같은 페이지 안의 섹션으로 이동한다.(`src/config/nav.ts`)
- 연락 섹션으로는 헤더 오른쪽의 Contact 버튼으로 간다. 메뉴에는 Contact 를 두지 않는다.(2026-11-12 사용자 결정)
- 푸터 메뉴는 Home · About · Projects · Contact 다.
- **현재 메뉴 표시**: 헤더 바로 아래까지 올라온 섹션의 메뉴에 밑줄과 강조색을 준다.(`src/shared/util/useSectionSpy.ts`)
    - 기준 자리는 메뉴로 이동했을 때 섹션이 멈추는 자리(`scroll-mt-header`)다. 메뉴를 누르면 그 메뉴가 항상 강조된다.
    - 여러 섹션이 올라와 있으면 가장 뒤의 것을 강조한다. 다음 섹션이 올라올 때까지 유지한다.
    - 히어로에서는 Home 을 강조한다. 마지막 메뉴 섹션이 다 지나가면 아무것도 강조하지 않는다.
    - 페이지 끝에 막혀 기준 자리까지 올라오지 못한 섹션은, 스크롤이 맨 아래에 닿았을 때 화면에 보이면 강조한다.
    - 처음 안은 화면 가운데에 걸친 섹션이었다. 화면 절반보다 짧은 기술 섹션으로 이동하면 다음 섹션이 강조돼서 바꿨다.
- **헤더 고정**: 헤더는 처음부터 화면 위에 붙어 있다.(요구사항 12, `src/widgets/header/HeaderBar.tsx`)
    - 맨 위에서는 바탕이 없고, 스크롤을 시작하면 바탕을 반투명으로 흐린다.
    - 메뉴로 섹션에 갈 때는 헤더 높이만큼 덜 올라가 제목이 헤더에 가리지 않는다.(`src/style/tokens/layout.css` 의 `scroll-mt-header`)

### 모바일 메뉴

요구사항 9번이다. 아래 기획안을 사용자가 모두 채택했다.(요구사항 11) 구현은 `src/widgets/header/HeaderBar.tsx` 에 있다.

- **전환 폭**: 768px 미만에서 햄버거 메뉴로 바꾼다. Tailwind 의 `md` 경계다.
- **좁은 화면의 헤더**: 로고와 메뉴 버튼만 한 줄에 둔다. 메뉴 4개와 Contact 버튼은 패널로 옮긴다.
- **패널**: 메뉴 버튼을 누르면 헤더 바로 아래에 화면 폭으로 펼친다. 메뉴 4개를 세로로 놓고 그 아래에 Contact 버튼을 둔다.
    - 바탕은 헤더와 같은 `glass` 다. 층은 `z-overlay` 다.(`docs/theme.md` 3절)
        - 뒤의 화면은 어둡게 덮지 않고 스크롤도 잠그지 않는다. 패널이 화면의 일부만 가린다.
- **닫기**: 메뉴 버튼을 다시 누름 · 항목을 누름 · `Esc` · 패널 밖을 누름. 화면이 768px 이상으로 넓어져도 닫힌다.
    - 항목을 누르면 패널이 다 닫힌 뒤에 그 섹션으로 이동한다. 누른 항목이 이동 도중에 사라지면 브라우저가 스크롤을 멈춘다.
- **현재 메뉴 표시**: 패널의 항목에도 같은 기준으로 강조색을 준다.
- **아이콘**: 메뉴 버튼은 닫혀 있을 때 줄 3개, 열려 있을 때 ✕ 다. `shared/ui/icon` 의 `menu` · `close` 다.

### 링크 연결

다른 페이지로 가는 링크다.

| 요소                    | 목적지         | 근거                                                    |
| ----------------------- | -------------- | ------------------------------------------------------- |
| View All Projects       | `/work`        | `src/features/featuredProjects/ui/FeaturedProjects.tsx` |
| 작업 카드의 열기 아이콘 | `/work/<slug>` | `src/entities/project/services/project.services.ts`     |
| More About Me           | `/about`       | `src/features/about/ui/About.tsx`                       |

- 작업 원문에 `href` 가 있으면 카드는 그 주소로 간다.
- 카드 주소의 `slug` 는 저장소를 연동하면 `id` 로 바뀐다.([admin/](../admin/README.md) 요구사항 10)
- 목적지 페이지에는 아직 제목만 있다.([work/](../work/README.md) · [about/](../about/README.md))

**GitHub 는 프로필 주소로 새 탭에서 연다.** 주소를 아직 받지 못해 지금은 `#top` 을 가리킨다.(`src/config/site.ts`)
LinkedIn 은 두지 않는다.(요구사항 8)
`http` 로 시작하는 주소에는 `target="_blank"` 와 `rel="noopener noreferrer"` 를 붙인다. 주소를 넣으면 바로 새 탭으로 열린다.(`src/widgets/footer/Footer.tsx`)

### 이메일

- 연락 버튼은 `Get in Touch` 1개다. 메일 주소 버튼은 따로 두지 않는다.(2026-11-12 사용자 결정)
- 버튼에 마우스를 올리거나 키보드로 초점을 주면 문구가 메일 주소로 바뀐다. 버튼 폭은 변하지 않는다.(`src/features/contact/ui/Contact.tsx`)
- 터치 화면에서는 문구가 바뀌지 않는다. 마우스 오버가 없기 때문이다.
- 누르면 `mailto:` 로 메일 앱을 연다.
- 메일 주소 복사와 복사됨 토스트는 두지 않는다. 채택했다가, 메일 주소 버튼을 없애면서 함께 뺐다.(2026-11-12 사용자 결정)

### 임시 값

- 소개 섹션의 숫자 3개는 원본 값이다. 사용자가 나중에 바꾼다.(`src/features/about/model/about.constants.ts`)
- 4번째 작업 카드는 썸네일이 없어 임시 이미지를 표시한다.(`content/projects.ts`)

## 모션

낙서 디자인이라 **선이 그려지는** 연출을 공통으로 쓴다.(`src/shared/ui/drawnPath/DrawnPath.tsx`)
페이지를 처음 그릴 때 실행하는 연출은 히어로에만 둔다. 나머지는 스크롤하거나 방문자가 조작할 때 실행한다.

| 요소             | 계기                | 연출                                       | 도구          | 토큰                                         | 동작 줄이기      |
| ---------------- | ------------------- | ------------------------------------------ | ------------- | -------------------------------------------- | ---------------- |
| 히어로 낙서      | 처음 그릴 때 한 번  | 왕관 · 밑줄 · 번개가 선으로 그려진다       | framer-motion | `DURATION.slow` · `EASE.enter`               | 다 그려진 상태   |
| 히어로 이름      | 처음 그릴 때 한 번  | 마커로 칠하듯 왼쪽부터 드러난다            | framer-motion | `DURATION.slower` · `EASE.enter`             | 보이는 상태      |
| 말풍선           | 처음 그릴 때 한 번  | 이름 다음에 튀어나온다                     | framer-motion | `SPRING.follow`                              | 보이는 상태      |
| 히어로 낙서      | 창 안의 포인터 이동 | 포인터 반대쪽으로 살짝 밀린다              | framer-motion | `SPRING.follow`                              | 움직이지 않음    |
| 헤더             | 스크롤 시작         | 바탕이 반투명으로 바뀐다                   | CSS           | `duration-fast` · `ease-move`                | 바로 바뀜        |
| 작업 카드        | 화면에 처음 들어옴  | 아래에서 차례로 올라온다(한 번만)          | framer-motion | `DURATION.base` · `STAGGER.base`             | 보이는 상태      |
| 작업 카드        | hover · focus       | 살짝 떠오르고 썸네일이 커진다              | CSS           | `duration-fast` · `ease-move`                | 색만 바뀜        |
| 기술 타일        | hover               | 아이콘이 한 번 흔들린다                    | CSS           | `duration-base` · `ease-move`                | 움직이지 않음    |
| 모바일 메뉴 패널 | 메뉴 버튼           | 위에서 내려오며 드러난다. 닫힐 때는 반대로 | framer-motion | `DURATION.fast` · `EASE.enter` · `EASE.exit` | 바로 열리고 닫힘 |
| 소개 숫자        | 화면에 처음 들어옴  | 0 부터 세어 올라간다                       | framer-motion | `DURATION.slower`                            | 최종 숫자        |
| 섹션 제목 밑줄   | 화면에 처음 들어옴  | 선으로 그려진다                            | framer-motion | `DURATION.slow` · `EASE.enter`               | 다 그려진 상태   |
| 가장자리 붓 자국 | 스크롤              | 본문보다 느리게, 서로 다른 속도로 움직인다 | GSAP          | ScrollTrigger                                | 움직이지 않음    |

- 무한 반복하는 연출은 두지 않는다.(`docs/motion.md` 금지사항, WCAG 2.2.2)
- 한 요소에 도구 2개를 함께 쓰지 않는다.(`docs/motion.md` 1절)
- 히어로 낙서는 포인터가 히어로 밖에 있어도 브라우저 창 어디서든 따라 움직인다.(2026-11-12 사용자 결정, `src/features/hero/ui/HeroIntro.tsx`)
- 붓 자국은 본문의 50~75% 속도로 움직인다. 붓 자국마다 속도가 다르다.(2026-11-12 사용자 결정, `src/widgets/backdrop/Backdrop.tsx`)
- 등장 연출의 순서는 낙서 → 이름 → 말풍선이다. 이름은 낙서가 반쯤 그려졌을 때 시작한다.(`src/features/hero/model/hero.motions.ts`)
- 기술 타일에는 초점을 받는 요소가 없어 hover 에만 흔들린다.(`src/features/skills/ui/Skills.tsx`)
- 작업 카드는 hover · focus 때 테두리가 `brand` 색으로 바뀐다. 동작 줄이기에서는 이 색만 바뀐다.(`src/features/featuredProjects/ui/ProjectCard.tsx`)

## 반응형

코드에 있는 배치다. 섹션마다 `flex-wrap` 으로 줄이 바뀐다.
경계 폭은 고정 값이 아니다. 각 영역의 기준 폭을 더한 값이 경계가 된다. 히어로는 글 440px + 캐릭터 380px + 간격과 여백이다.(`src/features/hero/ui/Hero.tsx`)

| 화면 폭              | 배치                                                   |
| -------------------- | ------------------------------------------------------ |
| 넓음 (약 920px 이상) | 히어로 글과 캐릭터가 좌우, 소개의 3개 영역이 한 줄     |
| 좁음 (약 920px 미만) | 히어로 캐릭터가 글 아래로, 소개 · 연락이 세로로 쌓인다 |
| 768px 미만           | 헤더에 로고와 메뉴 버튼만. 메뉴와 Contact 는 패널로    |
| 모바일 (390px)       | 작업 카드 한 열                                        |

## 접근성 · 성능 고려

- 손글씨 장식 문구(말풍선, `Ideas Design…`, `Let's Build…`, `Good Ideas…`)는 `aria-hidden` 이다. 같은 뜻이 본문에 있다.
- 아이콘만 있는 링크(작업 열기, 외부 프로필)에는 `aria-label` 이 있다.
- 히어로 이미지는 WebP 다(85KB). 화면 폭에 맞는 크기는 `next/image` 가 내려 준다.(`src/features/hero/ui/HeroVisual.tsx`)
- 세어 올라가는 숫자는 스크린 리더에 최종 값만 읽어 준다.(`src/features/about/ui/CountUp.tsx`)
- 모바일 메뉴 버튼은 `aria-expanded` 와 `aria-controls` 를 갖고, 이름은 「메뉴 열기」 · 「메뉴 닫기」 로 바뀐다. 크기는 44px 이상이다.
- 모바일 메뉴를 `Esc` 로 닫으면 초점이 메뉴 버튼으로 돌아간다. 닫힌 패널은 초점을 받지 않는다.
- 등장 연출이 레이아웃을 밀지 않게 한다. 목표는 CLS 0, Lighthouse 성능 90 이상이다. Lighthouse 는 아직 재지 않았다.
