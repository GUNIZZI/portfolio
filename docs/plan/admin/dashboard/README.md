# 대시보드 (`/admin/dashboard`) — 기획

사이트에 누가 얼마나, 무엇을 보러 오는지 한 화면에서 보는 관리 화면이다.
Google Analytics(GA)가 모은 방문 통계를 읽어 요약한다. 고치는 기능은 없다.

이 문서는 **신규 화면 기획**이다.(`../../README.md` 3.1)
요구사항에 없어 기획안으로 채웠던 항목은 사용자가 모두 채택했다.(요구사항 13) 정하지 않은 것은 [검토 필요 사항](#검토-필요-사항)에 「미정」 으로 남아 있다.
1차(블록 1~4번)와 추적 코드는 구현했다.(2026-11-20, `src/features/dashboard/` · `src/entities/analytics/` · `src/_app/SiteAnalytics.tsx`) 2차 가운데 최근 30분 방문자는 먼저 만들었다.(2026-11-24 사용자 결정, `src/features/dashboard/ui/RealtimeVisitors.tsx`) 방문자 추이의 꺾은선 그래프도 만들었다.(2026-11-25, `src/features/dashboard/ui/TrendChart.tsx`) 페이지별 조회수의 가로 막대와 2차의 나머지 3개는 아직이다.
로그인과 세션은 [로그인 기획](../login/README.md)을 그대로 따른다.

## 요구사항

사용자가 정한 요구사항이다. 모두 2026-11-17 에 정했다.

1. **관리 화면에서 Google Analytics 와 연동해 방문자 추이 · 트래픽 사용량 · 메뉴별 접근수 같은 정보를 본다.** 관리 측면의 대시보드다.
2. **블록은 8개다.** 요약 카드 · 방문자 추이 · 페이지별 조회수 · 프로젝트별 조회수 · 유입 경로 · 주요 행동 · 방문 환경 · 최근 30분 방문자다.
3. **1차로 앞의 4개를, 2차로 뒤의 4개를 만든다.**
4. **기간은 7일 · 30일 · 90일에서 고르고 처음 값은 30일이다.** 날짜를 직접 고르지 않는다.
5. **전송량, 연령 · 성별 · 관심사, 이탈률 · 전환 퍼널, 방문자 개인 단위의 기록은 넣지 않는다.** 전송량은 Vercel 사용량 화면으로 가는 링크만 둔다.
6. **주소는 `/admin/dashboard` 다. 메뉴는 대시보드 · 프로젝트 · 소개 · 경력 4개다.** → 제작 과정을 더해 5개로 바꿨다.(2026-11-27, [제작 과정 관리 기획](../colophon/README.md) 요구사항 2 · 5)
7. **로그인한 뒤의 첫 화면은 대시보드다.**
8. **데이터는 1시간마다 다시 받고, 새로 고침 버튼을 둔다.** 기준 시각과 하루쯤 늦게 반영된다는 안내를 적는다.
9. **관리 화면은 수집하지 않는다.**
10. **그래프는 꺾은선과 가로 막대 2종만 쓴다.**
11. ~~공개 화면에 GA 로 방문 통계를 모은다고 적는다.~~ **수집 고지는 넣지 않는다.**(2026-11-20 사용자 결정) 국내에서만 쓰는 사이트라 넣지 않기로 했다.
12. **관리 화면에도 GNB 영역을 만들어 넣는다.**
13. **이 문서에 `제안` 으로 적었던 기획안을 모두 채택한다.**(2026-11-17)
14. **소개 → 경력 → 프로젝트 → 대시보드 순으로 만든다.**(2026-11-17) 대시보드가 마지막이다.
15. **추가한 화면의 기록도 대시보드에 남긴다.**(2026-11-28) 기획 뷰어에서 본 문서의 조회수를 블록 하나로 보여 준다.

## 정책

### 구성

| 순서 | 블록               | 보여 주는 것                                                          | 단계               |
| ---- | ------------------ | --------------------------------------------------------------------- | ------------------ |
| 1    | 요약 카드          | 방문자 · 세션 · 조회수 · 평균 참여 시간. 카드마다 직전 기간 대비 증감 | 1차                |
| 2    | 방문자 추이        | 일별 방문자와 조회수. 꺾은선 그래프                                   | 1차                |
| 3    | 페이지별 조회수    | 홈 · 소개 · 프로젝트 목록 · 제작 과정의 조회수와 비율                 | 1차                |
| 4    | 프로젝트별 조회수  | 프로젝트 상세마다 조회수와 평균 참여 시간                             | 1차                |
| 5    | 유입 경로          | 직접 입력 · 검색 · 외부 링크 · 소셜의 세션 수                         | 2차                |
| 6    | 주요 행동          | 메일 버튼 클릭 수, GitHub 링크 클릭 수                                | 2차                |
| 7    | 방문 환경          | 기기 비율, 국가 상위 5개                                              | 2차                |
| 8    | 최근 30분 방문자   | 최근 30분의 접속자 수                                                 | 2차. 먼저 만들었다 |
| 9    | 기획 문서별 조회수 | 기획 뷰어에서 본 문서마다 조회수와 평균 참여 시간                     | 요구사항 15        |

- 블록은 9개다.(요구사항 2 · 15) 1차에는 1~4번만 그리고, 2차에 5~8번을 그 아래에 더한다.(요구사항 3)
- 9번 기획 문서별 조회수는 프로젝트별 조회수 바로 아래에 둔다.(2026-11-28 사용자 결정, `src/features/dashboard/ui/Dashboard.tsx`) 2차 블록을 만들면 그 블록들은 이 아래에 놓는다.
- 8번 최근 30분 방문자는 2차의 나머지보다 먼저 만들었다.(2026-11-24 사용자 결정) 자리는 기간 줄 바로 아래다.([와이어프레임 S-02](./wireframe.html#s02) 1번)
- 메뉴는 대시보드 · 프로젝트 · 소개 · 경력 · 제작 과정 5개다.(요구사항 6) 「GNB」 절
- 이 화면에는 고치는 기능이 없다. 읽기만 한다.
- 전송량은 그리지 않는다. Vercel 사용량 화면으로 가는 링크를 둔다.(요구사항 5) GA 콘솔로 가는 링크도 함께 둔다.
- 연령 · 성별 · 관심사, 이탈률 · 전환 퍼널, 방문자 개인 단위의 기록은 넣지 않는다.(요구사항 5)

### GNB

관리 화면의 맨 위에 두는 한 줄이다. 이 문서가 GNB 의 정책을 갖고, 다른 관리 기획은 이 절을 가리킨다.

- **로그인을 뺀 모든 관리 화면에 GNB 를 둔다.**(요구사항 12)
- 왼쪽부터 로고 · 메뉴 5개 · 테마 버튼 · 사이트 보기 · 로그아웃이다.(`src/widgets/adminHeader/AdminHeader.tsx`)
- 로고를 누르면 대시보드로 간다.
- 지금 있는 화면의 메뉴를 강조한다. 등록 · 수정 화면은 자기가 속한 메뉴를 강조한다. 어느 메뉴인지는 주소로 가린다.(`src/widgets/adminHeader/AdminNav.tsx`)
- 메뉴를 옮겨도 GNB 는 다시 그리지 않고 본문만 바꾼다.(`src/app/admin/(panel)/layout.tsx`)
- **밑줄은 하나다.** 메뉴를 선택하면 밑줄이 해당 메뉴로 이동하면서 글자 너비에 맞게 늘어나거나 줄어든다. 공개 헤더와 같은 밑줄이다.(2026-11-18 사용자 결정, `src/shared/ui/navIndicator/NavIndicator.tsx`)
- 사이트 보기는 공개 화면의 홈을 새 탭으로 연다. 로그아웃은 세션을 지우고 로그인으로 간다.([로그인 기획](../login/README.md) 「세션 · 로그아웃」)
- 페이지 제목 위에 두고, 스크롤하면 함께 올라간다. **좁은 화면에서는 메뉴만 아랫줄로 내려 고르게 벌려 놓는다.** 윗줄에는 로고와 사이트 보기 · 로그아웃 · 테마 버튼이 남는다.(2026-11-18 사용자 결정) 메뉴를 버튼으로 접지 않는다.
- **테마 버튼으로 다크와 라이트를 바꾼다.** 로그아웃의 오른쪽에 있다.(2026-11-18 사용자 결정, `src/widgets/adminHeader/AdminHeader.tsx`) 처음 방문의 테마와 저장은 [홈 기획](../../home/README.md) 「테마」 와 같다.
- 밑줄이 옮겨 가는 것과 화면을 옮기는 동안의 진행 선 말고는 연출을 두지 않는다.(2026-11-24 사용자 결정, `src/widgets/adminHeader/AdminNavProgress.tsx`)
- 저장하지 않은 내용이 있는 화면에서 메뉴나 로고를 눌러도 묻지 않고 옮긴다. 고친 내용은 남지 않는다.(2026-11-17 사용자 결정)
- 항목별 명세는 [와이어프레임 S-01](./wireframe.html#s01)의 「GNB」 표에 있다.

### 기간

- 기간은 7일 · 30일 · 90일 3가지다. 처음 값은 30일이다.(요구사항 4)
- 기간에 오늘은 넣지 않는다. GA 가 오늘 값을 다 모으지 못했기 때문이다.
- 기간을 바꾸면 최근 30분 방문자 수를 제외한 모든 통계가 함께 갱신된다.
- **고른 기간은 주소에 남긴다.** `?days=7` 처럼 적는다. 30일은 처음 값이라 주소에 적지 않는다. 3가지가 아닌 값이 오면 30일로 그린다.

### 블록별 규칙

- **요약 카드**: 증감은 직전 기간의 값과 견준 비율이다. 직전 기간의 값이 0이면 비율 대신 「—」 를 적는다.
- **방문자 추이**: 가로는 날짜, 세로는 수다. 선은 방문자와 조회수 2개다. 집계값이 없는 날짜는 0으로 표시한다. 두 선은 같은 세로 눈금을 쓴다. 방문자는 `brand-soft` 실선, 조회수는 `info` 점선이다. 포인터를 올리면 그날의 값을 적는다. 표는 접어 두고 「표로 보기」 를 누르면 편다.(2026-11-25 사용자 결정, `src/features/dashboard/ui/TrendChart.tsx` · `VisitorTrend.tsx`)
- **페이지별 조회수**: 공개 화면의 메뉴 4개만 센다. 프로젝트 상세는 4번 블록이 따로 센다. 404 와 관리 화면은 넣지 않는다.
- **기획 문서별 조회수**: 주소(`/plan/<기획 폴더>`)를 뷰어의 메뉴에 적힌 이름(`관리 > 대시보드`)으로 바꿔 적는다. 조회수가 많은 순으로 놓고, 조회수가 0인 문서도 적는다. **이름을 누르면 뷰어의 그 문서를 새 탭으로 연다.** 문서의 목록은 `pnpm plan-index` 가 만든다.(`src/config/planDocs.ts`) 목록에 없는 주소는 표에서 뺀다. 부품 견본과 지운 문서다.
- **기획 뷰어의 방문은 요약 카드 · 방문자 추이 · 최근 30분 방문자에 함께 들어간다.** 뷰어도 공개 화면이다.(2026-11-28 사용자 결정)
- **프로젝트별 조회수**: 주소(`/project/<id>`)를 프로젝트 제목으로 바꿔 적는다. **공개 · 비공개를 모두 보여 주고 조회수가 많은 순으로 놓는다.** 조회수가 0인 프로젝트도 적는다. **제목을 누르면 프로젝트 수정으로 간다.**
- **삭제한 프로젝트의 조회수는 표에서 뺀다.** 제목과 이을 프로젝트가 없다. 요약 카드의 합계에는 남는다.
- **유입 경로**: GA 가 나눈 갈래(직접 입력 · 검색 · 외부 링크 · 소셜)를 세션 수로 적는다. **외부 링크는 사이트별로 상위 5개를 함께 적는다.**
- **주요 행동**: 공개 화면의 메일 버튼과 GitHub 링크를 누른 횟수다. 「수집」 절의 클릭 이벤트가 있어야 값이 생긴다.
- **방문 환경**: 기기는 데스크톱 · 모바일 · 태블릿의 비율, 국가는 세션 수 상위 5개다.
- **최근 30분 방문자**: 최근 30분 동안 사이트를 방문한 사용자 수다. 선택한 기간과 관계없이 한 줄로 표시하며, 방문자가 없으면 0명으로 표시한다.(`src/features/dashboard/ui/RealtimeVisitors.tsx`)
- 최근 30분 방문자는 관리 화면을 보는 방문을 빼지 못한다. GA 의 실시간 보고서에 주소 차원이 없다.(`src/entities/analytics/repositories/analytics.repositories.ts` 의 `getRealtimeActiveUsers`)

### 갱신

- 서버가 GA 에서 받은 값을 1시간 동안 간직하고, 그동안에는 다시 받지 않는다.(요구사항 8)
- 새로 고침 버튼을 누르면 간직한 값을 버리고 다시 받는다.(요구사항 8) 버리기 전에 GA 를 한 번 불러 보고, 닿지 못하면 버리지 않는다.(`src/entities/analytics/services/analytics.services.ts` 의 `checkAnalyticsRefresh`)
- 화면에 기준 시각을 적고, 「GA 의 통계는 하루쯤 늦게 반영됩니다」 라고 안내한다.(요구사항 8)
- 최근 30분 방문자 수는 화면을 열 때마다 새로 불러온다.

### 수집

대시보드가 읽을 값을 공개 화면에서 모으는 규칙이다. 이 기획의 전제다.

- 공개 화면의 모든 페이지에 GA 추적 코드를 넣는다. 관리 화면(`/admin` 아래)에는 넣지 않는다.(요구사항 9, `src/app/(site)/layout.tsx`)
- 페이지를 이동할 때마다 조회 1건으로 집계한다. 새로고침 없이 이동한 경우도 포함한다.
- 클릭 이벤트 2개를 더한다. 연락 섹션의 메일 버튼과 푸터의 GitHub 링크다. 2차에서 주요 행동 블록이 읽는다.
- 공개 화면에 수집 고지와 동의 배너를 두지 않는다.(요구사항 11)
- 공개 화면에서 관리 화면으로 페이지를 새로 받지 않고 옮겨 가면 추적 코드가 남아 관리 화면의 주소도 모인다. 대시보드는 값을 읽을 때 `/admin` 아래의 주소를 뺀다.(`src/entities/analytics/repositories/analytics.repositories.ts`)
- 측정 ID 가 없으면 추적 코드를 넣지 않는다.(`src/_app/SiteAnalytics.tsx`)
- **기획 뷰어에도 추적 코드를 넣는다.**(요구사항 15) 뷰어는 Next 밖의 정적 파일이라, 배포할 파일을 만들 때 뷰어(`index.html`)의 복사본에 넣는다. 원본에는 넣지 않는다.(`scripts/publish-plan-viewer.mjs`, [기획 규칙](../../README.md) 1번)
- **뷰어에서 보는 문서를 바꿀 때마다 조회 1번으로 센다.** 주소는 `/plan/<기획 폴더>` 다(`/plan/admin/dashboard`). 뷰어가 주소 해시로 문서를 바꿔 GA 가 이동을 스스로 세지 못하므로 직접 보낸다. 문서 안에서 화면을 옮기는 것은 세지 않는다.
- 와이어프레임을 뷰어 없이 바로 연 방문은 세지 않는다. 손으로 쓰는 와이어프레임에는 추적 코드를 넣지 않는다.(2026-11-28 사용자 결정)
- 관리자가 공개 화면을 본 것은 다른 방문과 구별하지 못한다. 함께 세어진다.
- 광고 차단 도구를 쓰는 방문은 세어지지 않는다. 화면의 수는 실제보다 적다.

### 받지 못했을 때

- 화면을 처음 열 때 GA 에 닿지 못하면 블록 대신 오류 상태를 그린다. 메뉴는 그대로 둔다. 다른 관리 화면은 그대로 쓸 수 있다.
- 지금 구현은 GA 속성 ID 가 없을 때만 블록 전체를 오류 상태로 그린다. GA 에 닿지 못한 때에는 블록마다 오류를 그린다. 블록을 따로 받아 모두 실패했는지를 한곳에서 알지 못한다.(`src/features/dashboard/ui/Dashboard.tsx`)
- **블록 하나만 받지 못하면 해당 블록에만 오류를 표시하고 나머지 통계는 정상적으로 표시한다.**
- 새로 고침에 실패하면 간직하던 값을 그대로 두고, 받지 못했다고 알린다.
- 추적 코드를 적용한 직후처럼 집계된 값이 없으면 데이터 없음 상태를 표시한다. 조회에 실패한 경우에는 오류 상태를 표시한다.

### 다른 기획에 닿는 곳

- 로그인한 뒤의 첫 화면이 대시보드로 바뀐다.(요구사항 7) [로그인 기획](../login/README.md)의 「로그인」 과 `/admin` 의 동작이 따른다.
- 메뉴가 4개로 바뀐다.(요구사항 6) [프로젝트 관리 기획](../README.md) · [소개 관리 기획](../about/README.md) · [경력 관리 기획](../experiences/README.md)의 메뉴가 따른다.
- 공개 화면에 추적 코드가 더해졌다. 클릭 이벤트는 2차에 더한다. 수집 고지는 넣지 않는다.(요구사항 11)

## 모션

**관리 화면에는 연출을 두지 않는다.** [프로젝트 관리 기획](../README.md)의 「모션」 과 같다. 예외는 GNB 의 밑줄과 진행 선 2개다.(2026-11-18 · 2026-11-24 사용자 결정, 「GNB」 절) 그래프도 그려지는 연출 없이 바로 그린다.

## 반응형

**데스크톱을 기준으로 만든다.** 요약 카드는 한 줄에 4개, 좁은 화면에서는 2개씩 놓는다. 표는 가로로 스크롤한다.

## 접근성 · 성능 고려

- **그래프마다 같은 값을 표로도 제공한다.** 그래프는 스크린 리더로 읽을 수 없다.
- 증감은 색으로만 나타내지 않는다. 「▲ 12%」 처럼 기호와 숫자를 함께 적는다.
- 기간 선택은 지금 고른 값을 `aria-pressed` 나 `aria-current` 로 알린다.
- 새로 고침의 결과는 `role="status"` 로 알린다.
- 블록별로 데이터를 불러오고 준비되는 대로 표시한다. 한 블록의 응답이 늦어도 다른 블록은 먼저 표시할 수 있다.
- 공개 화면에 추적 코드를 넣은 뒤 성능 목표를 다시 잰다.([홈 기획](../../home/README.md) 검토 필요 사항 9번)
- 관리 화면의 코드와 그래프 코드는 공개 화면의 번들에 넣지 않는다.
