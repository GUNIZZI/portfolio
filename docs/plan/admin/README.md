# 프로젝트 관리 (`/admin/projects`) — 기획

포트폴리오에 싣는 프로젝트를 등록하고, 고치고, 공개 여부와 순서를 정하는 관리 화면이다.
공개 화면과 따로 두고 관리자 1명만 들어온다.

이 문서는 **신규 화면 기획**이다.(`../README.md` 3.1)
요구사항에 없어 기획안으로 채웠던 항목은 사용자가 모두 채택했다.(요구사항 23) 정하지 않은 것은 [검토 필요 사항](#검토-필요-사항)에 「미정」 으로 남아 있다.
로그인과 관리 화면의 머리(메뉴)는 구현했다(2026-11-17). 로그인의 기획은 [login/](./login/README.md) 에 따로 있다. 프로젝트는 아직 `content/projects.ts` 를 읽는다.

## 요구사항

사용자가 정한 요구사항이다. 모두 2026-11-12 에 정했다.

1. **포트폴리오 등록 관리를 위한 관리 기능을 추가한다.**
2. **관리 대상은 포트폴리오(프로젝트)만이다.** 기술 · 소개는 다루지 않는다. → 바꿨다. 요구사항 16
3. **배포는 Vercel 에 하고, 나중에 한다.**
4. **저장소는 Firebase 가 아니어도 된다. 저렴하게 쓸 수 있는 곳을 고른다.**
5. **프로젝트 상세 항목(역할 · 기간 · 기술 · 링크 · 본문)은 나중에 정한다. 지금은 관리 방식만 기획한다.**
6. **관리 기획은 공개 화면 기획과 따로 둔다.**
7. **아래 5가지는 기획안대로 간다.**
    - entity 에 `actions` 계층을 둔다.
    - 기획과 커밋의 구역에 `관리` 를 더한다.
    - 입력 · 스위치 · 다이얼로그 · 토스트는 지금의 토큰으로 `src/shared/ui/` 에 새로 만든다.
    - `/project-add` 스킬은 지운다.
    - 프로젝트 본문은 MDX 가 아니라 Markdown 으로 쓴다. → 바꿨다. 요구사항 12
8. **저장소는 Firestore + Firebase Auth + Vercel Blob 조합으로 한다. 기능 개발과 연동은 당장 하지 않고 적어만 둔다.**
9. **로그인은 Firebase Auth 를 쓰고, 관리자 계정은 Firebase Auth 에 등록해서 쓴다.** → 로그인 기획으로 옮겼다. 요구사항 20
10. **프로젝트는 `slug` 가 아니라 `id` 로 구분한다. `id` 는 저장소가 발급한다.**
11. **공개 프로젝트가 없으면 홈의 프로젝트 섹션을 감추지 않고, 프로젝트가 없다고 보여 준다.**
12. **프로젝트 본문은 Tiptap 에디터로 쓴다.** Kozipsa 가 쓰는 에디터다. Markdown 은 쓰지 않는다. 본문은 에디터가 내는 HTML 로 저장한다.(2026-11-16)
13. **로그인은 이메일과 비밀번호로 한다. 세션은 2시간 동안 유지한다.**(2026-11-17) → 로그인 기획으로 옮겼다. 요구사항 20
14. **비밀번호는 서버에서 확인한다. 관리자는 `ADMIN_UID` 환경 변수와 UID 가 같은 계정 1개다.**(2026-11-17) → 로그인 기획으로 옮겼다. 요구사항 20
15. **관리 기획에서는 「작업」 을 「프로젝트」 라고 부른다.**(2026-11-17)
16. **소개 데이터도 저장소에서 관리한다.** 소개 페이지의 경력 · 인트로 · 일하는 방식 · 기술 묶음과 홈의 소개 문단 · 숫자다. 홈의 기술 아이콘은 다루지 않는다.(2026-11-17)
17. **프로젝트를 먼저 저장소로 옮기고, 소개는 그다음에 옮긴다.**(2026-11-17) → 바꿨다. 요구사항 24
18. **관리 화면의 메뉴는 프로젝트 · 소개 · 경력 3개다.**(2026-11-17) → 대시보드를 더해 4개로 바꿨다. 요구사항 22
19. **소개 · 경력 관리의 기획은 이 문서와 따로 둔다.** 소개는 `docs/plan/admin/about/`, 경력은 `docs/plan/admin/experiences/` 다.(2026-11-17)
20. **로그인의 기획은 이 문서와 따로 `docs/plan/admin/login/` 에 둔다.** `/admin` 과 `/admin/login` 이 로그인이다.(2026-11-17)
21. **프로젝트 목록의 주소는 `/admin/projects` 다.**(2026-11-17)
22. **관리 화면의 메뉴에 대시보드를 더한다. 로그인한 뒤의 첫 화면은 대시보드다.** 기획은 `docs/plan/admin/dashboard/` 에 있다.(2026-11-17)
23. **이 문서에 `제안` 으로 적었던 기획안을 모두 채택한다.**(2026-11-17) 나가기 확인 창은 채택하지 않고 뺐다.
24. **소개 → 경력 → 프로젝트 → 대시보드 순으로 만든다.**(2026-11-17) 경력을 먼저 만들기 때문에, 경력의 프로젝트 연결은 프로젝트를 옮길 때 `slug` 에서 `id` 로 바꾼다.

## 정책

### 접근

- `/admin` 아래의 모든 화면은 로그인한 관리자만 볼 수 있다. 서버에서 세션을 검사한다.
- 로그인하지 않고 들어오면 [로그인](./login/wireframe.html#s01)으로 보낸다.
- 로그인 수단 · 관리자 판별 · 세션 기간은 [로그인 기획](./login/README.md)이 갖는다.
- 관리 화면은 검색 색인에서 뺀다.

### 목록

- 공개 · 비공개 프로젝트를 모두 순서대로 보여 준다.
- 열은 순서 · 썸네일 · 제목 · 분류 · 공개 · 수정 일시다.
- **검색과 페이지 나누기는 두지 않는다.** 프로젝트가 많지 않다.
- 공개 스위치는 목록에서 바로 바꾼다. 바꾸면 곧바로 저장한다.
- 제목을 누르면 [S-03 프로젝트 수정](./wireframe.html#s03)으로 간다.

### 순서

- 순서는 [P-02 순서 변경 창](./wireframe.html#p02)에서 바꾼다.
- 행을 끌거나 위 · 아래 버튼으로 옮긴다. 버튼은 키보드로도 옮길 수 있게 하기 위해서다.
- 저장을 눌러야 반영한다. 취소하면 바꾸기 전으로 돌아간다.
- 새로 등록한 프로젝트는 맨 뒤에 놓는다.

### 등록 · 수정

입력 항목이다. 규칙은 지금의 스키마를 따른다.(`src/entities/project/model/project.schemas.ts`)

| 항목        | 필드        | 필수                 | 규칙                                    |
| ----------- | ----------- | -------------------- | --------------------------------------- |
| 제목        | `title`     | 필수                 | 1자 이상                                |
| 분류        | `category`  | 필수                 | 1자 이상                                |
| 요약        | `summary`   | 필수                 | 1자 이상                                |
| 상세 주소   | `href`      | 선택                 | 비우면 프로젝트 상세를 가리킨다         |
| 썸네일      | `image`     | 선택                 | 없으면 공개 화면이 임시 이미지를 그린다 |
| 대체 텍스트 | `image.alt` | 썸네일이 있으면 필수 | 1자 이상                                |
| 공개        | `published` | —                    | 스위치                                  |

- 프로젝트는 `id` 로 구분한다. `id` 는 등록할 때 저장소가 발급하고 입력받지 않는다. 등록한 뒤에는 바뀌지 않는다.(요구사항 10)
- 공개 화면의 프로젝트 상세 주소도 `id` 를 쓴다(`/work/<id>`).
- **분류는 이미 있는 분류에서 선택하거나 새로 입력한다.** 같은 분류를 다른 철자로 적지 않게 하기 위해서다.
- **새 프로젝트는 비공개로 시작한다.** 다 쓰기 전에 공개 화면에 나오지 않게 하기 위해서다.
- **썸네일은 PNG · JPG · WebP 이고 5MB 까지다.**
- 썸네일의 가로 · 세로 크기는 올릴 때 파일에서 읽어 함께 저장한다. 입력받지 않는다.
- 썸네일을 바꾸거나 지우면 이전 파일도 저장소에서 지운다.
- 필수 항목이 비었거나 규칙에 맞지 않으면 저장 버튼을 누를 수 없고, 항목마다 오류 문구를 보여 준다.
- 저장하면 목록으로 돌아가 [P-03 토스트](./wireframe.html#p03)를 띄운다.
- 저장하지 않고 나가도 묻지 않는다. 고친 내용은 남지 않는다.(2026-11-17 사용자 결정)
- 글자 수 제한은 정하지 않았다.

### 삭제

- 삭제는 [P-01 삭제 확인 창](./wireframe.html#p01)을 거친다.
- 프로젝트 문서와 썸네일 파일을 함께 지운다. 되돌릴 수 없다.

### 공개 화면 반영

- 공개 화면은 공개 프로젝트만 순서대로 그린다.
- 등록 · 수정 · 삭제 · 공개 전환 · 순서 변경은 저장한 직후 공개 화면에 반영한다. 서버가 프로젝트 목록의 캐시를 지운다.
- 공개 프로젝트가 0건이면 홈의 프로젝트 섹션을 그대로 두고, 카드 대신 프로젝트가 없다는 문구를 보여 준다.(요구사항 11) **문구는 「아직 등록된 프로젝트가 없습니다」 다.**

### 기존 프로젝트 이전

- 지금의 4건과 `public/images/projects/` 의 이미지는 스크립트로 저장소에 한 번 옮긴다.
- 옮긴 뒤 `content/projects.ts` 와 `/project-add` 스킬을 지운다.(요구사항 7)

## 모션

**관리 화면에는 연출을 두지 않는다.** 반복해서 쓰는 화면이라 기다리는 시간을 만들지 않는다.

- 버튼의 색이 짧게 바뀌는 것은 연출로 치지 않는다. 관리 화면의 버튼은 `effect` 기본값(`default`)이고, 면이 밀려 들어오는 `sweep` 은 쓰지 않는다.(2026-11-18 사용자 결정, `src/shared/ui/button/button.md` 「hover · 포커스」)
- 스위치의 손잡이가 옮겨 가는 것도 같다.(`src/shared/ui/switch/switch.md`)
- 예외가 2곳 있다. 확인 창과 토스트는 Kozipsa 의 것처럼 옅어지며 나타나고 사라진다.(2026-11-18 사용자 결정, `src/shared/ui/alertDialog/alertDialog.md` 「연출」, `src/shared/ui/toast/Toast.md` 「연출」)

## 반응형

**데스크톱을 기준으로 만든다.** 좁은 화면에서는 표를 가로로 스크롤하고, 폼은 라벨이 입력 위로 올라간다.

## 데이터

### 저장소

요구사항 8에서 정한 조합이다. 비용이 들지 않는다. 연동은 당장 하지 않으며, 요금제와 한도는 가입할 때 다시 확인한다.

| 용도          | 서비스             | 요금제          | 고른 이유                                         |
| ------------- | ------------------ | --------------- | ------------------------------------------------- |
| 프로젝트 문서 | Firebase Firestore | Spark(무료)     | 카드를 등록하지 않고, 쓰지 않아도 멈추지 않는다   |
| 로그인        | Firebase Auth      | Spark(무료)     | Firestore 와 같은 프로젝트에서 쓴다               |
| 이미지        | Vercel Blob        | Hobby 무료 한도 | Firebase Storage 는 종량제(Blaze) 가입이 필요하다 |

- Supabase 는 문서 · 로그인 · 이미지를 한 곳에서 무료로 쓸 수 있다. 무료 프로젝트는 1주일 동안 요청이 없으면 멈춘다. 공개 화면이 캐시로 그려져 요청이 드물기 때문에 고르지 않았다.

### 항목

| 항목                                         | 지금                 | 바뀌는 것                                                                                                                           |
| -------------------------------------------- | -------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `slug`                                       | 있다                 | `id` 로 바뀐다. 저장소가 발급한다                                                                                                   |
| `title` · `category` · `summary` · `href`    | 있다                 | 그대로다                                                                                                                            |
| `image.src`                                  | `/` 로 시작하는 경로 | 이미지 저장소의 주소                                                                                                                |
| `image.alt` · `image.width` · `image.height` | 있다                 | 그대로다. 크기는 올릴 때 읽는다                                                                                                     |
| `published`                                  | 없다                 | 공개 여부                                                                                                                           |
| `order`                                      | 배열의 순서          | 숫자                                                                                                                                |
| `createdAt` · `updatedAt`                    | 없다                 | 서버가 기록한다                                                                                                                     |
| 역할 · 기간 · 기술 · 링크 · 본문             | 원문에 항목을 뒀다   | 공개 화면의 프로젝트 상세가 읽는다.([work/](../work/README.md) 「데이터」) 관리 화면의 입력은 아직 없다. 본문은 Tiptap 의 HTML 이다 |

### 읽고 쓰는 곳

| 동작 | 경로                                                                |
| ---- | ------------------------------------------------------------------- |
| 읽기 | 서버 `page` → `project.services` → `project.repositories` → 저장소  |
| 쓰기 | 폼 → `project.actions`(서버 액션) → `project.repositories` → 저장소 |

- 저장소를 부르는 곳은 `repositories` 하나다.(`docs/architecture.md` 4절)
- 쓰기는 서버에서 세션을 다시 검사하고, 지금의 zod 스키마로 검증한다.
- 공개 화면은 저장소를 직접 부르지 않는다. 서버가 읽어 캐시한 결과를 그린다.

### 구현할 때 바뀌는 규칙 문서

요구사항 7에서 정한 것이다. 코드가 생길 때 문서를 함께 고친다.

| 문서                             | 바뀌는 곳                                               |
| -------------------------------- | ------------------------------------------------------- |
| `docs/architecture.md` 1절 · 4절 | 데이터가 저장소로 바뀌고, entity 에 `actions` 가 생긴다 |
| `src/shared/ui/`                 | 입력 · 스위치 · 다이얼로그 · 토스트와 각 문서           |
| `.claude/skills/project-add/`    | 지운다                                                  |
| `src/entities/project/README.md` | 원문 위치와 파일 표                                     |

## 접근성 · 성능 고려

- 입력마다 `label` 을 잇고, 오류 문구는 `aria-describedby` 로 입력에 잇는다.
- 공개 스위치는 `role="switch"` 다. 목록에서는 어느 프로젝트의 스위치인지 이름에 넣는다.
- 다이얼로그를 열면 포커스를 창 안에 두고, 닫으면 열었던 버튼으로 돌려준다.
- 삭제 확인 창은 처음 포커스를 취소에 둔다.
- 순서는 끌지 않고 버튼만으로도 바꿀 수 있다.
- 토스트는 `role="status"` 로 알린다.
- 관리 화면의 코드는 공개 화면의 번들에 넣지 않는다.
