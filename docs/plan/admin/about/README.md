# 소개 관리 (`/admin/about`) — 기획

소개 페이지와 홈의 소개 섹션에 보이는 문구를 고치는 관리 화면이다.
인트로 · 일하는 방식 · Skill 관리 · 홈 소개를 한 화면에서 섹션별로 고친다.

이 문서는 **신규 화면 기획**이다.(`../../README.md` 3.1)
요구사항에 없어 기획안으로 채웠던 항목은 사용자가 모두 채택했다.(요구사항 7) 정하지 않은 것은 [검토 필요 사항](#검토-필요-사항)에 「미정」 으로 남아 있다.
구현했다(2026-11-17). 소개 문구를 저장소로 옮겼고, 공개 화면과 관리 화면이 entity `about` 으로 읽고 쓴다.(`src/entities/about/` · `src/features/aboutEditor/`)
로그인과 세션은 [로그인 기획](../login/README.md)을, GNB 는 [대시보드 기획](../dashboard/README.md)의 「GNB」 를 그대로 따른다.
경력은 [경력 관리 기획](../experiences/README.md)이 따로 다룬다.

## 요구사항

사용자가 정한 요구사항이다. 모두 2026-11-17 에 정했다.

1. **소개 데이터도 저장소에서 관리한다.**
2. **범위는 소개 페이지의 경력 · 인트로 · 일하는 방식 · 기술 묶음과 홈의 소개 문단 · 숫자다.** 홈의 기술 아이콘은 다루지 않는다.
3. **프로젝트를 먼저 저장소로 옮기고, 소개는 그다음에 옮긴다.** → 바꿨다. 요구사항 8
4. **관리 화면의 메뉴는 대시보드 · 프로젝트 · 소개 · 경력 4개다.**
5. **소개 관리의 기획은 프로젝트 관리 기획과 따로 둔다.**
6. **소개와 경력의 기획도 따로 둔다.** 이 문서는 소개만 다룬다.
7. **이 문서에 `제안` 으로 적었던 기획안을 모두 채택한다.**(2026-11-17) 나가기 확인 창은 채택하지 않고 뺐다.
8. **소개 → 경력 → 프로젝트 → 대시보드 순으로 만든다.**(2026-11-17) 소개가 가장 먼저다.

2번의 경력은 [경력 관리 기획](../experiences/README.md)에 있다.

## 정책

### 소개 내용

섹션은 4개다. 순서는 공개 화면에 보이는 순서를 따른다.

| 순서 | 섹션        | 보이는 곳                 | 고칠 수 있는 것                                |
| ---- | ----------- | ------------------------- | ---------------------------------------------- |
| 1    | 인트로      | 소개 페이지의 인트로      | 소개 문단, 성장 경로, 성장 경로 아래 한 줄     |
| 2    | 일하는 방식 | 소개 페이지의 일하는 방식 | 4가지의 제목과 설명                            |
| 3    | Skill 관리  | 소개 페이지의 기술        | 8개 묶음의 이름, 내용(쓴 곳 한 줄), Skill 이름 |
| 4    | 홈 소개     | 홈의 소개 섹션            | 소개 문단, 숫자 3개의 값 · 기호 · 이름         |

- 소개 내용에는 등록과 삭제가 없다. 섹션마다 1건을 고치기만 한다.
- **섹션마다 저장 버튼을 둔다.** 저장하는 문서가 섹션마다 1개이기 때문이다. 다른 섹션에 고친 내용이 있어도 누른 섹션만 저장한다.
- **섹션의 이름은 화면에 적힌 대로 쓴다.** 3번째 섹션은 「기술 묶음」 에서 「Skill 관리」 로 바꿨다.(2026-11-18 사용자 결정, `src/features/aboutEditor/model/aboutEditor.constants.ts`) 저장소의 문서 이름 `skillGroups` 는 그대로다.
- **일하는 방식은 4개, Skill 묶음은 8개, 숫자는 3개로 고정한다.** 개수는 소개 기획이 정했다.([소개 기획](../../about/README.md) 「일하는 방식」 · 「기술」) 내용만 고친다.
- **숫자의 아이콘은 입력받지 않는다.** 아이콘은 코드에 있는 이름으로 고른다.(`src/shared/ui/icon/Icon.tsx`)
- **소개 문단 · 성장 경로 · 묶음 안의 Skill 이름은 더하고 빼고 순서를 바꿀 수 있다.** 지금 값이 길이가 다른 목록이다.(`src/entities/about/model/about.schemas.ts`) 고치는 방식은 「목록 고치기」 에 있다.
- 소개 문단은 1줄 이상, 성장 경로는 2개 이상, 묶음 안의 Skill 이름은 1개 이상이어야 한다.
- 필수 항목이 비었으면 그 섹션의 저장 버튼을 누를 수 없고, 항목마다 오류 문구를 보여 준다.
- 저장하면 화면에 머물고 [P-01 토스트](./wireframe.html#p01)를 띄운다.
- **공개 여부는 두지 않는다.** 저장하면 바로 공개 화면에 반영한다.
- 글자 수 제한은 정하지 않았다.

### 목록 고치기

길이가 바뀌는 목록은 2가지 방식으로 고친다. 성장 경로와 Skill 이름은 줄 목록에서 칩 목록으로 바꿨다.(2026-11-18 사용자 결정. 구현하면서 바꾼 화면에 기획을 맞췄다)

| 방식    | 쓰는 곳                         | 컴포넌트                                        |
| ------- | ------------------------------- | ----------------------------------------------- |
| 줄 목록 | 인트로와 홈 소개의 소개 문단    | `src/features/aboutEditor/ui/ListField.tsx`     |
| 칩 목록 | 성장 경로, 묶음 안의 Skill 이름 | `src/features/aboutEditor/ui/ChipListField.tsx` |

줄 목록

- 줄마다 입력과 위 · 아래 · 빼기 버튼이 있다. 첫 줄의 위와 끝 줄의 아래는 누를 수 없다.
- 더하기 버튼을 누르면 맨 아래에 빈 줄이 생긴다.

칩 목록

- 이름을 옆으로 늘어놓고, 자리가 모자라면 다음 줄로 넘긴다.
- **이름을 끌어서 순서를 바꾼다.** 끄는 동안에는 놓을 자리에 선만 세우고, 놓았을 때 한 번 옮긴다. 끄는 동안 바로 옮기면 폭이 다른 이름끼리 자리가 계속 뒤바뀐다.
- **키보드로는 순서를 바꾸지 않는다.**(2026-11-18 사용자 결정) 더하기와 빼기는 키보드로 할 수 있다.
- 목록 아래에 「드래그해서 순서를 변경.」 이라고 안내한다.
- **이름에 마우스를 올리면 테두리와 면의 색을 바꿔 끌 수 있음을 알린다.**(2026-11-18 사용자 결정)
- 이름마다 빼기(×) 버튼이 있다.
- **목록 아래의 입력에 이름을 적고 「+ 추가」 를 누르거나 Enter 를 치면 맨 끝에 더한다.** 입력이 비었으면 「+ 추가」 를 누를 수 없다. Enter 로 더해도 섹션은 저장하지 않는다.
- 더한 이름은 고칠 수 없다. 빼고 다시 더한다.

두 방식 모두 최소 개수만 남으면 빼기를 누를 수 없다.

### 나가기

- 저장하지 않고 나가도 묻지 않는다. 저장하지 않은 섹션의 내용은 남지 않는다.(2026-11-17 사용자 결정) GNB 의 메뉴나 로고를 누를 때도 같다.

### 공개 화면 반영

- 저장한 직후 공개 화면에 반영한다. 서버가 소개 페이지와 홈의 캐시를 지운다.

### 기존 내용 이전

- 소개 문구는 스크립트로 저장소에 한 번 옮겼다(2026-11-17). 관리 기능 가운데 가장 먼저 한다.(요구사항 8)
- 옮긴 뒤 아래 상수를 지웠다.
    - `src/features/aboutIntro/model/aboutIntro.constants.ts`
    - `src/features/workPrinciples/model/workPrinciples.constants.ts`
    - `src/features/skillGroups/model/skillGroups.constants.ts`
    - `src/features/about/model/about.constants.ts`(숫자의 아이콘 이름은 코드에 남긴다)

## 반응형

**데스크톱을 기준으로 만든다.** 좁은 화면에서는 폼의 라벨이 입력 위로 올라간다. [프로젝트 관리 기획](../README.md)의 「반응형」 과 같다.
좁은 화면에서 줄 목록의 버튼은 입력 아래로 내려가고, 통계는 이름 · 값과 기호 · 문구 순으로 세로로 쌓인다.(`src/features/aboutEditor/ui/ListField.tsx` · `HomeForm.tsx`)

## 데이터

### 저장소

[프로젝트 관리 기획](../README.md)의 「저장소」 와 같은 Firestore 를 쓴다. 이미지는 다루지 않는다.

| 내용        | 두는 곳                         | 건수 |
| ----------- | ------------------------------- | ---- |
| 인트로      | 컬렉션 `about` 의 `intro`       | 1개  |
| 일하는 방식 | 컬렉션 `about` 의 `principles`  | 1개  |
| Skill 관리  | 컬렉션 `about` 의 `skillGroups` | 1개  |
| 홈 소개     | 컬렉션 `about` 의 `home`        | 1개  |

컬렉션과 문서의 이름은 기획안이다.

### 항목

| 내용        | 항목                                               | 지금                                                     | 바뀌는 것                                  |
| ----------- | -------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------ |
| 인트로      | 소개 문단 · 성장 경로 · 성장 경로 아래 한 줄       | `ABOUT_INTRO_LINES` · `GROWTH_PATH` · `GROWTH_PATH_NOTE` | 저장소에서 읽는다                          |
| 일하는 방식 | 4가지의 `title` · `description`                    | `WORK_PRINCIPLES`                                        | 저장소에서 읽는다                          |
| Skill 관리  | 8개의 `name` · `usage` · `items`                   | `SKILL_GROUPS`                                           | 저장소에서 읽는다                          |
| 홈 소개     | 소개 문단, 숫자 3개의 `value` · `suffix` · `label` | `ABOUT_LINES` · `ABOUT_STATS`                            | 저장소에서 읽는다. `icon` 은 코드에 남긴다 |
| 섹션마다    | `updatedAt`                                        | 없다                                                     | 서버가 기록한다                            |

### 읽고 쓰는 곳

| 동작 | 경로                                                             |
| ---- | ---------------------------------------------------------------- |
| 읽기 | 서버 `page` → `services` → `repositories` → 저장소               |
| 쓰기 | 폼 → `actions`(서버 액션) → `services` → `repositories` → 저장소 |

- 소개 내용은 entity `about` 이 다룬다.(`src/entities/about/README.md`)
- 쓰기는 서버에서 세션을 다시 검사하고 zod 스키마로 검증한다.(`docs/architecture.md` 4절 · 4.2절)
- 소개 페이지와 홈의 feature 는 상수를 읽지 않고, `page` 가 읽어 넘긴 값을 그린다.(`docs/architecture.md` 4절)

## 접근성 · 성능 고려

- 입력마다 `label` 을 잇고, 오류 문구는 `role="alert"` 로 입력 아래에 적는다.(`src/shared/ui/field/field.md`)
- 줄을 더하고 빼고 옮기는 버튼에는 어느 줄의 버튼인지 이름에 넣는다.
- 칩 목록의 빼기 버튼에는 어느 이름의 버튼인지를 읽어 준다.(`src/features/aboutEditor/ui/ChipListField.tsx`)
- 줄을 옮기면 옮긴 줄의 버튼에 포커스를 남긴다. 줄을 빼면 그다음 줄로 포커스를 보낸다.
- 토스트는 `role="status"` 로 알린다.
- 관리 화면의 코드는 공개 화면의 번들에 넣지 않는다.
