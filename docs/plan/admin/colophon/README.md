# 제작 과정 관리 (`/admin/colophon`) — 기획

「제작 과정」 페이지와 홈의 제작 과정 섹션에 보이는 글과 표를 고치는 관리 화면이다.
머리 · 과정 · 디자인 · 개발 과정 · 장치 · 사람이 한 일 · 기술과 폰트를 한 화면에서 섹션별로 고친다.

이 문서는 **신규 화면 기획**이다.(`../../README.md` 3.1)
2026-11-27 에 사용자가 방향을 채택했다. 요구사항에 없어 기획안으로 채운 항목에는 `제안` 을 붙였고, [검토 필요 사항](#검토-필요-사항)에서 확정한다.
구현했다(2026-11-27). 페이지의 글과 표를 entity `colophon` 으로 읽고 쓴다.(`src/entities/colophon/` · `src/features/colophonEditor/`)
로그인과 세션은 [로그인 기획](../login/README.md)을, GNB 는 [대시보드 기획](../dashboard/README.md)의 「GNB」 를 그대로 따른다.
화면의 틀과 저장 방식은 [소개 관리 기획](../about/README.md)과 같다.

## 요구사항

사용자가 정한 요구사항이다. 모두 2026-11-27 에 정했다. 6 · 7번은 2026-11-27 에, 8번은 2026-11-28 에 화면을 만든 뒤에 더했다.

1. **관리자에서 「제작 과정」 도 관리할 수 있게 한다.**
2. **소개 관리와 같은 구조로 만든다.** 내용을 저장소로 옮기고, 한 화면에서 섹션별로 저장하고, GNB 에 메뉴를 추가한다.
3. **글과 표의 내용만 고친다.** 섹션 7개의 구성과 순서, 과정 4단계와 이어지는 섹션, 계층 그림, 역할의 색은 코드에 남긴다. → 과정은 6 · 7번으로 바꿨다.
4. **기술 목록과 링크만 늘리고 줄인다.** 나머지 목록은 개수를 고정한다. → 모든 목록을 늘리고 줄인다. 7 · 8번
5. **메뉴의 이름은 「만든 방법」 이다.** → 「제작 과정」 으로 바꿨다. 9번
6. **과정(PROCESS)도 관리 대상에 넣는다.**
7. **과정의 단계도 추가하고 삭제할 수 있게 한다.**
8. **나머지 목록도 추가 · 삭제 · 순서 변경을 할 수 있게 한다.**
9. **이름은 「제작 과정」 하나로 부른다.**(2026-11-28) 공개 페이지의 「이 사이트는 이렇게」 와 관리 메뉴의 「만든 방법」 을 함께 바꿨다.

## 정책

### 내용

섹션은 7개다. 순서는 공개 화면에 보이는 순서를 따른다.(요구사항 2 · 3 · 6 · 7 · 8)

| 순서 | 섹션         | 보이는 곳                                  | 고칠 수 있는 것                                                  | 목록                  |
| ---- | ------------ | ------------------------------------------ | ---------------------------------------------------------------- | --------------------- |
| 1    | 머리         | 페이지의 머리, 홈의 제작 과정 섹션         | 한 줄 요약, 숫자의 이름 · 값, 집계 기준일                        | 숫자                  |
| 2    | 과정         | 페이지의 PROCESS 섹션, 홈의 제작 과정 섹션 | 단계의 이름 · 역할 · 이어지는 섹션                               | 단계                  |
| 3    | 디자인       | 페이지의 DESIGN 섹션                       | 단락의 제목 · 역할 · 설명                                        | 단락                  |
| 4    | 개발 과정    | 페이지의 DEVELOP 섹션                      | 단계의 제목 · 작업 내용 · 대시보드 적용 사례, 링크의 이름 · 주소 | 단계, 단계마다의 링크 |
| 5    | 장치         | 페이지의 GUARDRAILS 섹션                   | 장치의 이름 · 개수 · 점검 항목 · 적용 예                         | 장치                  |
| 6    | 사람이 한 일 | 페이지의 HUMAN 섹션                        | 제목 · 설명                                                      | 항목                  |
| 7    | 기술과 폰트  | 페이지의 STACK 섹션                        | 기술 이름, 폰트의 이름 · 견본 글꼴 · 쓰는 곳 · 라이선스          | 기술, 폰트            |

- 섹션에는 등록과 삭제가 없다. 섹션마다 1건을 고치고, 그 안의 목록을 더하고 뺀다.
- **섹션마다 저장 버튼을 둔다.** 다른 섹션에 고친 내용이 있어도 누른 섹션만 저장한다.(요구사항 2, [소개 관리 기획](../about/README.md) 「소개 내용」)
- **목록은 모두 더하고 빼고 순서를 바꿀 수 있다.**(요구사항 4 · 7 · 8) 고치는 방식은 「목록」 에 있다.
- 과정을 고치는 방식은 「과정」 에 있다.
- **코드에 남기는 것은 아래와 같다.**(요구사항 3, `src/features/colophon/model/colophon.constants.ts`)
    - 섹션의 영문 제목과 그 아래 한 줄
    - 역할 3개(나 · GPT · Claude)와 역할마다의 점 색
    - 견본 글꼴 3개와 글꼴을 그리는 클래스
    - 디자인 단락마다의 역할. 단락의 자리로 정한다
    - 계층 그림
    - 저장소 주소(`src/config/site.ts`)
- **디자인의 단락마다 역할을 고른다.**(`제안`) 단락의 개수와 순서가 바뀌므로 코드가 자리로 정할 수 없다. 과정의 단계와 같은 선택 상자다.
- **폰트마다 이름을 적고 견본 글꼴을 고른다.**(`제안`) 페이지는 폰트의 이름을 견본 글꼴로 적는다. 견본 글꼴은 이 사이트가 불러오는 Permanent Marker · Caveat · Noto Sans KR 가운데 고른다. 사이트가 불러오지 않는 폰트는 그 모양으로 보여 줄 수 없다.(`src/entities/colophon/model/colophon.constants.ts` 의 `COLOPHON_FONT_FACE`)
- **숫자의 값은 글로 받는다.** `113개` · `2026.11.12` 처럼 단위와 날짜가 섞여 있다. 집계 기준일도 글로 받는다.(`제안`)
- 필수 항목이 비었으면 그 섹션의 저장 버튼을 누를 수 없고, 항목마다 오류 문구를 보여 준다.
- 저장하면 화면에 머물고 [P-01 토스트](./wireframe.html#p01)를 띄운다.
- **공개 여부는 두지 않는다.** 저장하면 바로 공개 화면에 반영한다.
- 글자 수 제한은 정하지 않았다.

### 목록

**목록은 모두 더하고 빼고 순서를 바꿀 수 있다.**(요구사항 8)

| 목록             | 최소 | 고치는 방식 | 새 항목의 시작 값                     |
| ---------------- | ---- | ----------- | ------------------------------------- |
| 머리의 숫자      | 1개  | 카드 목록   | 빈 값                                 |
| 과정의 단계      | 1개  | 카드 목록   | 역할 「나」, 이어지는 섹션 「디자인」 |
| 디자인의 단락    | 1개  | 카드 목록   | 역할 「나」                           |
| 개발 과정의 단계 | 1개  | 카드 목록   | 빈 값, 링크 없음                      |
| 단계마다의 링크  | 0개  | 줄 목록     | 빈 값                                 |
| 장치             | 1개  | 카드 목록   | 빈 값                                 |
| 사람이 한 일     | 1개  | 카드 목록   | 빈 값                                 |
| 기술             | 1개  | 칩 목록     | —                                     |
| 폰트             | 1개  | 카드 목록   | 견본 글꼴 「Noto Sans KR」            |

- **카드 목록과 줄 목록은 항목마다 위 · 아래 · 빼기 버튼이 있다.** 첫 항목의 위와 끝 항목의 아래는 누를 수 없다. 최소 개수만 남으면 빼기를 누를 수 없다.(`src/features/colophonEditor/ui/RowActions.tsx`)
- 더하기 버튼을 누르면 맨 아래에 빈 항목이 생긴다. 필수 항목을 채우기 전에는 그 섹션을 저장할 수 없다.
- 개발 과정의 단계를 옮기면 그 단계의 링크도 함께 옮긴다.
- 칩 목록은 [소개 관리 기획](../about/README.md) 「목록 고치기」 의 칩 목록과 같다. 끌어서 순서를 바꾼다.
- **최소 개수와 새 항목의 시작 값은 기획안이다.**(`제안`) 최대 개수는 두지 않는다.
- 공개 화면은 개수에 맞춰 줄을 넘긴다. 숫자와 기술은 옆으로 놓고 자리가 모자라면 다음 줄로 넘긴다. 카드는 칸의 최소 폭을 채우는 만큼 한 줄에 놓는다.(`src/features/colophon/ui/Colophon.tsx`)

### 과정

단계는 1개 이상이고, 더하고 빼고 순서를 바꿀 수 있다.(요구사항 7) 버튼과 최소 개수는 「목록」 과 같다.

| 항목          | 입력      | 값                                                             |
| ------------- | --------- | -------------------------------------------------------------- |
| 이름          | 글        | 필수                                                           |
| 역할          | 선택 상자 | 나 · GPT · Claude 중 하나                                      |
| 이어지는 섹션 | 선택 상자 | 디자인 · 개발 과정 · 장치 · 사람이 한 일 · 기술과 폰트 중 하나 |

- **단계마다 역할과 이어지는 섹션을 고른다.**(`제안`) 단계의 개수와 순서가 바뀌므로 코드가 자리로 정할 수 없다.
- 이어지는 섹션은 페이지에서 그 단계를 눌렀을 때 내려가는 곳이다. 과정 아래에 있는 섹션 5개 가운데 고른다. 홈의 제작 과정 섹션에서는 단계를 누를 수 없어 쓰지 않는다.([제작 과정 기획](../../colophon/README.md) 「과정 한눈에」)
- 페이지는 넓은 화면에서 한 줄에 4개씩 놓고, 넘으면 다음 줄로 넘긴다.(`src/features/colophon/ui/ProcessSteps.tsx`)
- 공개 화면의 PROCESS 섹션에 적는 한 줄은 개수를 적지 않게 바꿨다. 「이 순서로 만들었습니다.」 로 시작한다.(`src/features/colophon/ui/Colophon.tsx`)

### 링크

개발 과정의 단계마다 링크를 0개 이상 둔다. 링크 하나는 이름과 주소 한 쌍이다.

- 이름과 주소는 모두 필수다.
- **주소는 `https://` 나 `/` 로 시작해야 한다.**(`제안`) 바깥 주소와 이 사이트 안의 경로만 받는다. 기획 뷰어의 주소(`/plan/index.html#admin/dashboard`)가 `/` 로 시작한다.([기획 규칙](../../README.md) 1번)
- 공개 화면은 링크를 모두 새 탭으로 연다.([제작 과정 기획](../../colophon/README.md) 「Claude 가 개발」)
- 더하고 빼고 순서를 바꾸는 방식은 「목록」 과 같다. 링크는 모두 빼도 된다.

### 처음 값

**한 번도 저장하지 않은 섹션은 코드의 처음 값을 그린다.**(`제안`)

- 공개 화면과 관리 화면이 같은 처음 값을 그린다. 관리 화면에는 그 섹션의 수정 일시를 적지 않는다.
- 섹션을 한 번 저장하면 그 뒤로는 저장소의 값을 쓴다.
- 처음 값은 2026-11-26 에 페이지를 만들 때 쓴 글이다. 개발 과정 · 장치 · 사람이 한 일의 글은 2026-11-28 에 사용자가 준 문구로 바꿨다.(`src/entities/colophon/model/colophon.constants.ts` 의 `COLOPHON_DEFAULT_CONTENT`)
- 소개 관리는 스크립트로 저장소에 한 번 옮겼다.([소개 관리 기획](../about/README.md) 「기존 내용 이전」) 이 화면은 옮기는 단계를 두지 않는다. 저장소에 문서가 없어도 공개 화면이 열린다.

### 나가기

- 저장하지 않고 나가도 묻지 않는다. 저장하지 않은 섹션의 내용은 남지 않는다. GNB 의 메뉴나 로고를 누를 때도 같다.([소개 관리 기획](../about/README.md) 「나가기」)

### 공개 화면 반영

- 저장한 직후 공개 화면에 반영한다. 서버가 「제작 과정」 페이지와 홈의 캐시를 지운다.
- 머리의 한 줄 요약과 과정의 단계는 홈의 제작 과정 섹션에도 보인다.([홈 기획](../../home/README.md) 「제작 과정 섹션」)

### 메뉴

- **GNB 의 5번째 메뉴로 「제작 과정」 을 둔다.**(요구사항 2 · 9) 메뉴의 순서는 [대시보드 기획](../dashboard/README.md) 「GNB」 가 갖는다.
- 메뉴의 이름은 공개 화면의 페이지명과 같다.(요구사항 9, [제작 과정 기획](../../colophon/README.md) 「페이지의 틀」)

| 내용         | 두는 곳                        | 건수 |

| 개발 과정    | 컬렉션 `colophon` 의 `develop` | 1개  |
| 장치         | 컬렉션 `colophon` 의 `guards`  | 1개  |
| 사람이 한 일 | 컬렉션 `colophon` 의 `human`   | 1개  |
| 기술과 폰트  | 컬렉션 `colophon` 의 `stack`   | 1개  |

컬렉션과 문서의 이름은 기획안이다.(`제안`)

### 항목

| 내용         | 항목                                                                | 전에 있던 곳             |
| ------------ | ------------------------------------------------------------------- | ------------------------ |
| 머리         | `summary`, 숫자마다의 `label` · `value`, `statsDate`                | `COLOPHON_SUMMARY` 등    |
| 과정         | 단계마다의 `title` · `role` · `sectionId`                           | `COLOPHON_PROCESS_STEPS` |
| 디자인       | 단락마다의 `title` · `role` · `description`                         | `COLOPHON_DESIGN_STEPS`  |
| 개발 과정    | 단계마다의 `title` · `work` · `example` · `links`(`label` · `href`) | `COLOPHON_DEVELOP_STEPS` |
| 장치         | 장치마다의 `name` · `count` · `prevents` · `example`                | `COLOPHON_GUARDS`        |
| 사람이 한 일 | 항목마다의 `title` · `description`                                  | `COLOPHON_HUMAN_WORKS`   |
| 기술과 폰트  | `techs`, 폰트마다의 `name` · `face` · `usage` · `license`           | `COLOPHON_TECH_LIST` 등  |
| 섹션마다     | `updatedAt`                                                         | 없다. 서버가 기록한다    |

전에 있던 곳은 모두 `src/features/colophon/model/colophon.constants.ts` 의 상수다. 지금은 처음 값으로 entity 에 있다.

### 읽고 쓰는 곳

| 동작 | 경로                                                             |
| ---- | ---------------------------------------------------------------- |
| 읽기 | 서버 `page` → `services` → `repositories` → 저장소               |
| 쓰기 | 폼 → `actions`(서버 액션) → `services` → `repositories` → 저장소 |

- 내용은 entity `colophon` 이 다룬다.(`src/entities/colophon/README.md`)
- 쓰기는 서버에서 세션을 다시 검사하고 zod 스키마로 검증한다.(`docs/architecture.md` 4절 · 4.2절)
- 공개 화면의 feature 는 `page` 가 읽어 넘긴 값을 그린다.(`src/app/(site)/colophon/page.tsx` · `src/app/(site)/page.tsx`)

## 접근성 · 성능 고려

- 입력마다 `label` 을 잇고, 오류 문구는 `role="alert"` 로 입력 아래에 적는다.(`src/shared/ui/field/field.md`)
- 목록의 항목은 `fieldset` 으로 묶고 `legend` 에 몇 번째인지 적는다.(`src/features/colophonEditor/ui/ItemFieldset.tsx`)
- 위 · 아래 · 빼기 버튼에는 어느 항목의 버튼인지 이름에 넣는다.(`src/features/colophonEditor/ui/RowActions.tsx`)
- 링크의 입력과 빼기 버튼에는 몇 단계의 몇 번째 링크인지 이름에 넣는다.(`src/features/colophonEditor/ui/LinkFields.tsx`)
- 토스트는 `role="status"` 로 알린다.
- 관리 화면의 코드는 공개 화면의 번들에 넣지 않는다.
