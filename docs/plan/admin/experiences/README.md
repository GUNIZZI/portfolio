# 경력 관리 (`/admin/experiences`) — 기획

소개 페이지의 경력 타임라인을 관리하는 화면이다.
회사마다 등록하고 고치며, 그 회사에서 한 프로젝트 목록을 함께 다룬다.

이 문서는 **신규 화면 기획**이다.(`../../README.md` 3.1)
요구사항에 없어 기획안으로 채웠던 항목은 사용자가 모두 채택했다.(요구사항 5) 정하지 않은 것은 [검토 필요 사항](#검토-필요-사항)에 「미정」 으로 남아 있다.
구현했다.(2026-11-18) 화면은 `src/features/experienceEditor/`, 데이터는 `src/entities/experience/` 다. 기획과 다르게 만든 곳은 「구현하면서 정한 것」 에 있다.
로그인과 세션은 [로그인 기획](../login/README.md)을, GNB 는 [대시보드 기획](../dashboard/README.md)의 「GNB」 를 그대로 따른다.
소개 문구는 [소개 관리 기획](../about/README.md)이 따로 다룬다.

## 요구사항

사용자가 정한 요구사항이다. 모두 2026-11-17 에 정했다.

1. **소개 데이터도 저장소에서 관리한다.** 경력이 그 가운데 하나다.
2. **프로젝트를 먼저 저장소로 옮기고, 소개는 그다음에 옮긴다.** 경력도 프로젝트 다음이다. → 바꿨다. 요구사항 6
3. **관리 화면의 메뉴는 대시보드 · 프로젝트 · 소개 · 경력 4개다.** → 제작 과정을 더해 5개로 바꿨다.(2026-11-27, [대시보드 기획](../dashboard/README.md) 요구사항 6)
4. **소개와 경력의 기획은 따로 둔다.** 이 문서는 경력만 다룬다.
5. **이 문서에 `제안` 으로 적었던 기획안을 모두 채택한다.**(2026-11-17) 나가기 확인 창은 채택하지 않고 뺐다.
6. **소개 → 경력 → 프로젝트 → 대시보드 순으로 만든다.**(2026-11-17) 경력은 프로젝트보다 먼저다.

## 정책

### 목록

- 회사를 모두 보여 준다. **순서는 입력받지 않고, 들어간 해가 늦은 회사부터 놓는다.** 공개 화면이 최신부터 그린다.([소개 기획](../../about/README.md) 「구성」)
- 열은 회사 · 기간 · 프로젝트 수 · 수정 일시다.
- **검색과 페이지 나누기는 두지 않는다.** 회사는 6곳이다.(`content/experiences.json`)
- 회사 이름을 누르면 [S-03 경력 수정](./wireframe.html#s03)으로 간다.

### 등록 · 수정

회사의 입력 항목이다. 규칙은 지금의 스키마를 따른다.(`src/entities/experience/model/experience.schemas.ts`)

| 항목             | 필드            | 필수 | 규칙                                                     |
| ---------------- | --------------- | ---- | -------------------------------------------------------- |
| 회사             | `company`       | 필수 | 1자 이상                                                 |
| 들어간 해        | `startYear`     | 필수 | 4자리 숫자                                               |
| 재직 중          | —               | —    | 켜면 떠난 해를 입력받지 않는다                           |
| 떠난 해          | `endYear`       | 필수 | 4자리 숫자. 들어간 해보다 앞설 수 없다. 재직 중이면 없다 |
| 요약             | `summary`       | 선택 | 비우면 공개 화면이 요약 줄을 그리지 않는다               |
| 실제 프로젝트 수 | `totalProjects` | 선택 | 1 이상의 숫자. 목록에 대표만 적은 회사에 준다            |

경력의 프로젝트 1줄의 입력 항목이다.

| 항목          | 필드        | 필수 | 규칙                                        |
| ------------- | ----------- | ---- | ------------------------------------------- |
| 이름          | `name`      | 필수 | 1자 이상                                    |
| 시기          | `date`      | 필수 | `2025.06` 또는 `2022`                       |
| 기술 태그     | `tags`      | 선택 | 태그 하나는 1자 이상                        |
| 프로젝트 연결 | `projectId` | 선택 | 등록된 프로젝트 중 하나. 없으면 잇지 않는다 |

- **경력은 `id` 로 구분한다.** `id` 는 등록할 때 저장소가 발급하고 입력받지 않는다. 프로젝트와 같은 방식이다.([프로젝트 관리 기획](../README.md) 요구사항 10)
- 경력의 프로젝트는 회사 안에서 더하고 뺀다. 0건이어도 저장할 수 있다.
- **경력의 프로젝트는 위 · 아래 버튼으로 순서를 바꾼다.** 키보드로도 옮길 수 있게 하기 위해서다. 새로 더한 줄은 맨 위에 놓는다. 공개 화면이 최근 프로젝트를 위에 그린다.
- **프로젝트 연결은 등록된 프로젝트 중에서 선택한다.** 공개 · 비공개를 모두 보여 주고 비공개에는 표시를 붙인다. 비공개 프로젝트에 이으면 공개 화면은 이름만 표시한다. 비공개 표시는 이름 뒤의 `(비공개)` 다.(2026-11-18 사용자 결정, `src/features/experienceEditor/ui/ProjectRow.tsx`)
- 이은 프로젝트를 삭제하면 그 연결도 없어진다. 공개 화면은 이름만 그린다.
- **기술 태그는 칩 목록으로 입력한다.** 소개 관리의 Skill 이름과 같은 방식이다.(2026-11-18 사용자 결정, `src/shared/ui/chipListField/ChipListField.tsx`)
- 필수 항목이 비었거나 규칙에 맞지 않으면 저장 버튼을 누를 수 없고, 항목마다 오류 문구를 보여 준다.
- 저장하면 경력 목록으로 돌아가 [P-02 토스트](./wireframe.html#p02)를 띄운다.
- 글자 수 제한은 정하지 않았다.

### 삭제

- 경력 삭제는 [P-01 삭제 확인 창](./wireframe.html#p01)을 거친다. 회사와 그 안의 프로젝트 목록을 함께 지운다. 되돌릴 수 없다.
- 경력을 지워도 이어 둔 프로젝트(entity `project`)는 지우지 않는다.
- 경력의 프로젝트 1줄을 빼는 것은 확인 창을 거치지 않는다. 저장하기 전에는 반영하지 않는다.

### 나가기

- 저장하지 않고 나가도 묻지 않는다. 고친 내용은 남지 않는다.(2026-11-17 사용자 결정) 등록과 수정에서 같다. GNB 의 메뉴나 로고를 누를 때도 같다.

### 공개 화면 반영

- 저장 · 삭제는 저장한 직후 공개 화면에 반영한다. 서버가 소개 페이지의 캐시를 지운다.
- 경력이 0건이면 소개 페이지의 경력 섹션을 그대로 두고, 목록 대신 경력이 없다는 문구를 보여 준다. 프로젝트가 0건일 때와 같은 방식이다.([프로젝트 관리 기획](../README.md) 요구사항 11)

### 기존 내용 이전

- 지금의 경력 6곳은 스크립트로 저장소에 한 번 옮긴다. 2026-11-18 에 옮겼다.
- 경력을 프로젝트보다 먼저 옮겼다.(요구사항 6) 그동안 프로젝트 연결은 `workSlug` 로 이었고, 프로젝트를 옮기면서 `projectId` 로 바꿨다.(2026-11-19, `src/entities/experience/model/experience.schemas.ts`)
- 옮긴 뒤 `content/experiences.json` 을 지운다. 지웠다.

## 데이터

### 저장소

[프로젝트 관리 기획](../README.md)의 「저장소」 와 같은 Firestore 를 쓴다. 이미지는 다루지 않는다.

| 내용 | 두는 곳              | 건수                |
| ---- | -------------------- | ------------------- |
| 경력 | 컬렉션 `experiences` | 회사 1곳이 문서 1개 |

컬렉션의 이름은 기획안이다. 경력의 프로젝트 목록은 회사 문서 안의 배열로 둔다.

### 항목

| 항목                                                              | 지금            | 바뀌는 것                                |
| ----------------------------------------------------------------- | --------------- | ---------------------------------------- |
| `slug`                                                            | 있다            | `id` 로 바뀐다. 저장소가 발급한다        |
| `company` · `startYear` · `endYear` · `summary` · `totalProjects` | 있다            | 그대로다                                 |
| `projects[].name` · `date` · `tags`                               | 있다            | 그대로다                                 |
| `projects[].projectId`                                            | `workSlug` 였다 | 프로젝트의 `id` 다. 2026-11-19 에 바꿨다 |
| `createdAt` · `updatedAt`                                         | 없다            | 서버가 기록한다                          |

### 읽고 쓰는 곳

| 동작 | 경로                                                             |
| ---- | ---------------------------------------------------------------- |
| 읽기 | 서버 `page` → `services` → `repositories` → 저장소               |
| 쓰기 | 폼 → `actions`(서버 액션) → `services` → `repositories` → 저장소 |

- entity `experience` 가 읽고 쓴다.(`src/entities/experience/`)
- 프로젝트 연결에 보여 줄 프로젝트 목록은 entity `project` 에서 읽는다.
- 쓰기는 서버에서 세션을 다시 검사하고 zod 스키마로 검증한다.(`docs/architecture.md` 4절 · 4.2절)

## 접근성 · 성능 고려

- 입력마다 `label` 을 잇고, 오류 문구는 `role="alert"` 로 입력 아래에 적는다.(`src/shared/ui/field/field.md`)
- 줄을 더하고 빼고 옮기는 버튼에는 어느 줄의 버튼인지 이름에 넣는다.
- 줄을 옮기면 옮긴 줄의 버튼에 포커스를 남긴다. 줄을 빼면 그다음 줄로 포커스를 보낸다.
- 삭제 확인 창은 처음 포커스를 취소에 둔다.
- 토스트는 `role="status"` 로 알린다.
- 관리 화면의 코드는 공개 화면의 번들에 넣지 않는다.
