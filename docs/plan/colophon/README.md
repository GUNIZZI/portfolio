# 제작 과정 (`/colophon`) — 기획

이 포트폴리오를 어떻게 만들었는지 보여 주는 페이지다. 컨셉을 정한 때부터 배포까지, 사람과 GPT 와 Claude 가 각각 무엇을 했는지 과정 순서로 담는다.

2026-11-26 에 사용자가 채택했다. [검토 필요 사항](#검토-필요-사항)은 모두 확정했다.
페이지는 구현했다.(2026-11-26, `src/app/(site)/colophon/page.tsx` · `src/features/colophon/`) 홈의 제작 과정 섹션도 같은 슬라이스가 그린다.([홈 기획](../home/README.md) 「제작 과정 섹션」)

## 요구사항

2026-11-25 와 2026-11-26 에 사용자가 정했다. 2026-11-11 첫 플랜에서 Phase 3 의 6번 화면으로 제안했던 페이지다.

1. **디자인 컨셉을 정하고, 디자인 레퍼런스를 전달하고, GPT 가 디자인하고, Claude 가 개발했다. 이 과정을 담는다.**
2. **AX 를 활용한 개발 과정을 더 상세하게 넣는다.**
3. **레퍼런스는 핀터레스트 같은 곳에서 검색해 모았다고 쓴다.**
4. **GPT 가 만든 시안은 그림 없이 글로만 설명한다.**
5. **개발 과정은 대시보드를 예로 따라간다.**
6. **컨셉 · 레퍼런스 · GPT 디자인은 한 섹션으로 묶는다. 섹션은 7개다.**
7. **컨셉은 원래 좋아하던 스트릿 · 그라피티에서 정했다. 개인 취향이다.**
8. **저장소는 공개 저장소다.**
9. **GPT 에는 레퍼런스와 컨셉, 구성 요소를 주고 시안을 요청했다.**
10. **디테일한 부분은 직접 수정하거나 요청하면서 진행했다.**
11. **들어오는 곳으로 메인 화면에 섹션을 하나 구성한다.**
12. **이름은 `HOW THIS SITE IS BUILT` 이다.**
13. **계층과 의존 방향을 한눈에 확인할 수 있도록 구조를 다이어그램으로 표시한다.**

## 정책

### 구성

**섹션은 7개이고 만든 순서대로 놓는다.**(요구사항 1 · 6)

| 순서 | 섹션                      | 내용                                                                       | 근거가 되는 파일                                         |
| ---- | ------------------------- | -------------------------------------------------------------------------- | -------------------------------------------------------- |
| 1    | 머리                      | 제목 `HOW THIS SITE IS BUILT`, 한 줄 요약, 만든 기간, 커밋 수, 저장소 링크 | `git log`                                                |
| 2    | 과정 한눈에               | 4단계 흐름 그림. 단계마다 역할을 적는다                                    | —                                                        |
| 3    | 디자인                    | 컨셉 정하기 · 레퍼런스 모으기 · GPT 가 디자인 · 토큰으로 옮김              | `docs/design.md`, `src/style/tokens/`                    |
| 4    | Claude 가 개발            | 기획 · 플랜 승인 · 구현 · 검증 · 커밋. 대시보드를 예로 따라감              | `CLAUDE.md`, `docs/plan/admin/dashboard/`                |
| 5    | AI 가 틀리지 않게 한 장치 | 규칙 문서 · 훅 · 스킬 · 에이전트 · ESLint, 각각이 막는 실수                | `CLAUDE.md`, `.claude/`, `docs/`, `eslint.config.mjs`    |
| 6    | 사람이 한 일              | 결정 · 승인 · 다듬기. AI 에 맡긴 것과 맡기지 않은 것의 경계                | 문서의 「사용자 결정」 기록                              |
| 7    | 기술과 구조               | 기술 이름, 계층과 의존 방향 그림, 폰트와 라이선스                          | `package.json`, `docs/architecture.md`, `docs/design.md` |

- 저장소의 코드와 문서를 바탕으로 작성한다. 커밋, 문서, 테스트 개수는 집계 기준일의 수치를 사용한다.
- 저장소에 근거가 없는 내용은 사용자가 준 것만 쓴다.(요구사항 7 · 9 · 10)

### 과정 한눈에

**4단계를 왼쪽에서 오른쪽으로 놓고, 단계마다 역할을 적는다.**(요구사항 1)

| 순서 | 단계                 | 역할   | 이어지는 섹션 |
| ---- | -------------------- | ------ | ------------- |
| 1    | 콘셉트 정하기        | 나     | 3번           |
| 2    | 참고 이미지 전달하기 | 나     | 3번           |
| 3    | 디자인한다           | GPT    | 3번           |
| 4    | 개발한다             | Claude | 4번           |

- 역할은 글자로 적는다. 색만으로 구별하지 않는다.
- 위 표의 4단계는 처음 값이다. 단계의 개수 · 순서 · 이름 · 역할 · 이어지는 섹션은 관리 화면에서 고친다.(2026-11-27 사용자 결정, [제작 과정 관리 기획](../admin/colophon/README.md) 「과정」)
- 단계를 누르면 이어지는 섹션으로 스크롤한다.(2026-11-26 사용자 결정)

### 디자인

**한 섹션에 4개 단락을 순서대로 둔다.**(요구사항 6)

| 순서 | 단락            | 내용                                                                                                              | 근거                                |
| ---- | --------------- | ----------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| 1    | 컨셉 정하기     | 원래 좋아하던 스트릿 · 그라피티에서 정했다. 개인 취향이다. 형광 마커 · 손글씨 · 낙서 · 캐릭터 일러스트로 나타냈다 | 요구사항 7, `docs/design.md` 머리말 |
| 2    | 레퍼런스 모으기 | 핀터레스트 같은 곳에서 검색해 모았다                                                                              | 요구사항 3                          |
| 3    | GPT 가 디자인   | 레퍼런스와 컨셉, 구성 요소를 주고 시안을 요청했다. 반응형 페이지 1개를 받았다                                     | 요구사항 9, `docs/design.md` 머리말 |
| 4    | 토큰으로 옮김   | 시안의 색 · 글자 크기 · 모서리에 이름을 붙였다. 라이트 값은 새로 정했다                                           | `docs/design.md` 원칙 1 · 1.1절     |

- **시안은 그림 없이 글로만 설명한다.**(요구사항 4)
- 레퍼런스로 삼은 사이트의 이름과 화면은 싣지 않는다.(요구사항 3)
- 시안에서 바꾼 것은 `docs/design.md` 4절의 표에서 고른다. 고르는 개수는 본문을 쓸 때 정한다.

### Claude 가 개발

**기능 하나가 만들어지는 한 바퀴를 5단계로 보여 주고, 대시보드를 예로 든다.**(요구사항 2 · 5)

| 순서 | 단계      | 하는 일                                                         | 대시보드의 예                                                   |
| ---- | --------- | --------------------------------------------------------------- | --------------------------------------------------------------- |
| 1    | 기획      | `/plan-write` 로 PRD · 유저 플로우 · 와이어프레임 3종을 쓴다    | `docs/plan/admin/dashboard/`                                    |
| 2    | 플랜 승인 | 정하지 않은 것을 「검토 필요 사항」 에서 사람이 하나씩 확정한다 | 12개 항목. 2026-11-17 · 11-20 · 11-25 에 확정                   |
| 3    | 구현      | 승인받은 범위 안에서 묻지 않고 만든다                           | `src/features/dashboard/` · `src/entities/analytics/`           |
| 4    | 검증      | `pnpm check` 를 통과시키고 화면을 Playwright 로 띄워 본다       | 테스트 `analytics.services.test.ts` · `dashboard.utils.test.ts` |
| 5    | 커밋      | 커밋 스킬이 관심사 단위로 나눠 커밋한다                         | 2026-11-20 1차 블록 4개, 2026-11-24 최근 30분 방문자            |

- 단계의 「하는 일」 은 `CLAUDE.md` 의 `# 규칙` · `## 검증` · `## 커밋` 을 근거로 쓴다.
- 대시보드의 기획 문서와 코드 폴더는 GitHub 저장소의 그 경로로 링크를 걸어 새 탭으로 연다. 관리 화면으로는 링크를 걸지 않는다.(2026-11-26 사용자 결정)
- 기획 단계에는 기획 뷰어에서 대시보드의 와이어프레임을 여는 링크를 하나 더 둔다. 주소는 `/plan/index.html#admin/dashboard` 이고 새 탭으로 연다.(2026-11-26 사용자 결정, [기획 규칙](../README.md) 1번)

### AI 가 틀리지 않게 한 장치

**장치마다 「무엇을 막는가」 를 한 줄로 적고, 실제로 걸리는 예를 하나씩 붙인다.**(요구사항 2)

| 장치      | 개수               | 막는 실수                               | 예                                                   | 근거가 되는 파일             |
| --------- | ------------------ | --------------------------------------- | ---------------------------------------------------- | ---------------------------- |
| 규칙 문서 | `CLAUDE.md` 와 9개 | 사람과 AI 가 서로 다른 규칙을 읽는 것   | AI 전용 요약본을 두지 않는다                         | `CLAUDE.md`, `docs/index.md` |
| 훅        | 3개                | 토큰 밖의 값, 맞지 않는 포맷, 평문 커밋 | `duration: 0.6` 을 쓰면 토큰을 쓰라고 알린다         | `.claude/hooks/`             |
| 스킬      | 7개                | 같은 일을 할 때마다 순서가 달라지는 것  | 커밋은 `/commit` · `/commit-quick` 으로만 한다       | `.claude/skills/`            |
| 에이전트  | 2개                | 훅과 린트가 검사하지 못하는 어긋남      | 모션을 고치면 동작 줄이기 분기를 점검한다            | `.claude/agents/`            |
| ESLint    | —                  | 계층을 거슬러 가져오는 것               | `entities` 가 `features` 를 가져오면 린트가 실패한다 | `eslint.config.mjs`          |

### 사람이 한 일

**AI 에 맡기지 않은 일을 적는다.**(요구사항 2)

- 정한 것: 컨셉, 디자인 채택, 기획의 「검토 필요 사항」. 문서에 「사용자 결정」 과 날짜로 남아 있다.
- 승인한 것: 플랜. 승인한 범위를 벗어나는 수정은 다시 허락을 받는다.(`CLAUDE.md` `# 규칙`)
- 다듬은 것: 디테일한 부분은 직접 수정하거나 요청하면서 진행했다.(요구사항 10)

### 기술과 구조

**글은 앞의 섹션보다 짧게 쓰고, 구조는 그림으로 보여 준다.**(요구사항 6 · 13)

- 기술은 이름만 나열한다. Next.js 16 · React 19 · TypeScript · Tailwind v4 · framer-motion · GSAP 이다.(`package.json`)
- 구조는 계층 5개(app · widgets · features · entities · shared)와 의존 방향을 그림으로 그린다. 화살표는 위에서 아래로 향한다.(요구사항 13, `docs/architecture.md` · `eslint.config.mjs`)
- 그림의 모양은 구현할 때 시안을 보고 사용자가 확인한다.(요구사항 13)
- 폰트는 이름과 라이선스를 함께 적는다. 라이선스는 구현할 때 폰트마다 공식 페이지에서 확인하고 `docs/design.md` 에도 적는다.(2026-11-26 사용자 결정)

### 페이지의 틀

- **페이지를 `(site)` 레이아웃 안에 둔다.** 헤더가 홈과 같다.(2026-11-26 사용자 결정, `src/app/(site)/colophon/page.tsx`)
- 추적 코드는 페이지에 따로 두지 않는다. 레이아웃이 갖고 있다.(`src/app/(site)/layout.tsx`)
- 본문 아래에 연락 섹션과 푸터를 둔다. 연락 섹션은 모든 페이지의 푸터 위에 있다.([홈 기획](../home/README.md) 「메뉴」)
- 배경에 이 페이지의 낙서를 둔다. 소개 페이지처럼 적게 둔다.(2026-11-26 사용자 결정, `src/features/colophonDoodles/`)
- **한글 이름은 「제작 과정」 이다.** 문서의 페이지명, 브라우저 탭의 제목, 대시보드의 라벨, 관리 화면의 메뉴가 모두 이 이름을 쓴다. 화면의 제목만 `HOW THIS SITE IS BUILT` 이다.(2026-11-28 사용자 결정) 전에는 페이지를 「이 사이트는 이렇게」, 관리 메뉴와 홈의 섹션을 「만든 방법」 으로 따로 불렀다.

- 표와 목록의 줄 수도 관리 화면에서 바꾼다. 이 문서에 적은 개수(디자인 4개 단락, 개발 5단계, 장치 5개, 폰트 3개)는 처음 값이다.(2026-11-28 사용자 결정, [제작 과정 관리 기획](../admin/colophon/README.md) 「목록」)

    - 개발 과정 표의 열 제목은 `단계` · `작업 내용` · `대시보드 적용 사례` 다. 2번째 단계의 이름은 「계획 검토 및 승인」 이다.
    - 장치 카드의 항목 이름은 「막는 실수」 에서 「점검 항목」 으로, 「예」 에서 「적용 예」 로 바꿨다.
    - 사람이 한 일의 제목은 「방향 정하기」 · 「작업 범위 승인하기」 · 「화면 다듬기」 다.
    - 섹션 제목 아래의 한 줄과 계층 그림의 설명도 바꿨다.(`src/features/colophon/ui/Colophon.tsx` · `src/features/colophon/model/colophon.constants.ts`)
- 이 문서의 「정책」 에 적은 글과 표의 값은 처음 값이다. 관리 화면에서 수정한 뒤에는 저장된 값을 화면에 표시한다.
- `page`에서 콘텐츠를 읽고 화면에 전달한다.(`src/app/(site)/colophon/page.tsx`)

## 접근성 · 성능 고려

- 구조 그림은 순서 있는 목록(`ol`)이다. 계층 이름과 설명이 글자라 그림 없이도 읽힌다. 화살표만 SVG 이고 `aria-hidden` 으로 가린다.(`src/features/colophon/ui/LayerDiagram.tsx`)
- 과정 그림은 순서 있는 목록(`ol`)으로 마크업한다. 단계 이름과 역할을 글자로 적어 그림 없이도 읽힌다.
- 역할은 색만으로 구별하지 않는다. 글자를 함께 적는다.
- 표의 열 제목에는 `th`를 사용한다. 좁은 화면에서 표만 가로로 스크롤하고 페이지는 밀리지 않는다.
