# 소개 (`/about`) — 기획

GUNI 가 어떤 개발자인지 홈보다 자세히 보여 주는 페이지다. 경력 · 일하는 방식 · 기술을 담는다.

사용자가 구성과 남은 결정을 맡겨, 제안이던 항목을 기획안대로 채택해 구현했다.(요구사항 8)
문구는 임시로 채웠고 사용자가 바꾼다. 남은 것은 [검토 필요 사항](#검토-필요-사항)에 있다.

## 요구사항

사용자가 정한 요구사항이다.

1. **경력은 기존 소개 페이지(`gunizzi.github.io/guni/about`)의 내용을 옮긴다.**(2026-11-16)
2. **경력은 회사 아래에 프로젝트 목록을 두는 2단으로 적는다.** 프로젝트에는 이름 · 시기 · 기술 태그가 있다.(2026-11-16)
3. **2014년 이후에 시작한 경력은 처음부터 펼치고, 그 이전은 접어 둔다.**(2026-11-16)
4. **회사마다 역할과 한 일을 한두 줄로 적는다.** 문구는 사용자가 쓴다.(2026-11-16)
5. **작업 상세가 있는 프로젝트는 `/work/<slug>` 로 잇는다.**(2026-11-16)
6. **옮긴 데이터는 임시 데이터로 엔티티에 먼저 넣어 둔다.** 화면 연결은 나중에 한다.(2026-11-16)
7. **기술은 분야별 8개 묶음으로 적는다.** 디자인 시스템 · 마크업 · 데이터 시각화 · 구조와 배포를 포함한다.(2026-11-16)
8. **남은 기획안은 알아서 정해 진행한다.** 제안이던 구성 · 성장 경로 · 접는 방법 · 모션을 기획안대로 채택한다.(2026-11-16)

홈 기획의 검토 필요 사항 4번(소개 연결)이 이 페이지를 가리킨다.([home/](../home/README.md))

## 정책

### 구성

| 순서 | 섹션          | 내용                                                             |
| ---- | ------------- | ---------------------------------------------------------------- |
| 1    | 인트로        | 큰 캐릭터 일러스트, 소개 문단, 성장 경로 한 줄                   |
| 2    | 경력 타임라인 | 최신부터. 회사 · 기간 · 요약, 그 아래 프로젝트 목록. 「경력」 절 |
| 3    | 일하는 방식   | 4가지. 「일하는 방식」 절                                        |
| 4    | 기술          | 분야별 묶음 8개. 「기술」 절                                     |
| 5    | 연락          | 모든 페이지에 붙는 연락 섹션(`widgets/contact`)                  |

- 섹션마다 feature 하나다. `aboutIntro` · `experienceTimeline` · `workPrinciples` · `skillGroups`, 연락은 모든 페이지에 붙는 위젯 `contact` 다.(`src/app/about/page.tsx`)
- 헤더와 푸터는 홈과 같다. 메뉴의 About 이 이 페이지이고, 여기서는 About 을 강조한다.([home/](../home/README.md) 「메뉴」)
- 배경은 공통 배경에 이 페이지의 낙서를 넣는다.(`src/features/aboutDoodles/`) 글이 많은 페이지라 홈보다 적게 둔다.
- 타임라인은 순서가 있는 정보라 프로젝트마다 시기를 앞에 둔다.
- **세로선 왼쪽에 회사에 들어간 해를 크게 적는다.**(2026-11-16 사용자 결정) 그 아래에 떠난 해를 작게 둔다. 세로선이 지나가면 점과 함께 강조색으로 켜진다.
    - 768px 미만에는 둘 자리가 없어 회사 이름 줄의 기간이 대신한다.(`src/features/experienceTimeline/ui/TimelineMarker.tsx`)
- 기술 묶음은 홈의 기술 타일보다 자세히 쓴다. 「기술」 절
- 성장 경로는 디자인 → 플래시 → 마크업 · JS → Vue → React · TS 다. 기존 페이지의 그림을 한 줄로 옮긴다.

### 일하는 방식

**4가지를 둔다. 화면을 만드는 방법만이 아니라 일 전체를 담는다.**(2026-11-16 사용자 결정)
처음 안은 3가지(규칙과 도구 · 움직임에 이유 · AI 와 함께)였는데 UI 개발에만 몰려 있었다.

| 순서 | 영역               | 원칙                                     |
| ---- | ------------------ | ---------------------------------------- |
| 1    | 제품 이해          | 화면보다 문제를 먼저 봅니다              |
| 2    | 디자인과 개발 사이 | 디자인과 개발의 언어를 둘 다 씁니다      |
| 3    | 구조               | 오래 쓸 구조를 먼저 잡습니다             |
| 4    | 협업               | 혼자 아는 것을 팀이 아는 것으로 바꿉니다 |

- 처음 안의 「규칙과 도구」 는 3번에, 「AI 와 함께」 는 4번의 설명에 넣었다.
- 「움직임에 이유를 둔다」 는 뺐다. 기술 묶음의 모션 항목과 사이트 자체가 보여 준다.
- 「도구는 바뀌어도 기준은 가져갑니다」 는 인트로의 성장 경로 아래에 한 줄로 둔다.
- 문구는 경력을 보고 쓴 초안이다. 사용자가 관리 화면에서 고친다.([소개 관리 기획](../admin/about/README.md))

### 기술

**분야별로 8개 묶음을 둔다.**(2026-11-16 사용자 결정) 처음 안은 6개(화면 · 상태 · 스타일 · 움직임 · 품질 · 협업)였다.
경력에 있는데 들어갈 자리가 없던 디자인 시스템 · 마크업 · 데이터 시각화 · 구조와 배포를 더했다.

| 순서 | 묶음               | 담는 것                                             | 근거가 되는 경력              |
| ---- | ------------------ | --------------------------------------------------- | ----------------------------- |
| 1    | UI · 디자인 시스템 | Shadcn UI, Storybook, UI Kit 설계, 컴포넌트 문서화  | Design System, UI Kit         |
| 2    | 프레임워크         | React, Next.js, Vue 2, Nuxt 2                       | KOCOM · NEWEN AI 의 프로젝트  |
| 3    | 언어 · 마크업      | TypeScript, JavaScript, HTML, CSS, 웹 표준 · 접근성 | 2009년부터 이어진 Markup · JS |
| 4    | 상태 · 데이터      | Zustand, Vuex, TanStack, Context, NextAuth          | Web Admin 들                  |
| 5    | 스타일             | Tailwind CSS, MUI                                   | Design System, Ris-K          |
| 6    | 모션 · 인터랙션    | framer-motion, GSAP, 이전에는 Flash 모션            | 이 사이트, TRIPLE 시기        |
| 7    | 데이터 시각화      | D3.js, AmChart, 대시보드 설계                       | 대시보드 다수                 |
| 8    | 구조 · 배포 · 협업 | Monorepo, CI/CD, SSR · CSR, Git, Notion, AI 협업    | KOCOM Web Management          |

- UI · 디자인 시스템을 맨 앞에 둔다. 디자인에서 출발해 디자인 시스템까지 만든다는 점이 이 경력의 특징이다.
- 묶음마다 어디에 썼는지 한 줄을 붙인다. 지금 문구는 임시다. 관리 화면에서 고친다.([소개 관리 기획](../admin/about/README.md))
- 「담는 것」 의 기술 이름은 경력 태그(`content/experiences.json`)에서 옮긴 초안이다. 사용자가 더하거나 뺀다.
- 디자인 도구와 Flash 개발은 묶음으로 두지 않는다. 지금 쓰지 않는 기술이다. 인트로의 성장 경로와 모션 묶음에서 언급한다.

### 경력

요구사항 1~5번이다.

| 단위     | 보여 주는 것                                                  |
| -------- | ------------------------------------------------------------- |
| 회사     | 이름 · 기간(`2014 – 2025`) · 재직 중 표시 · 역할과 한 일 요약 |
| 프로젝트 | 이름 · 시기(`2025.06` 또는 `2022`) · 기술 태그                |

- 회사는 6곳, 목록에 적은 프로젝트는 56개다. 2004년부터 지금까지다.(`content/experiences.json`)
- **목록에 대표 프로젝트만 적은 회사는 실제 수를 따로 적는다.**(2026-11-16 사용자 결정) NEWEN AI 는 10년 동안 50개 넘게 했는데 목록에는 「고객사 대시보드 40개+」 처럼 묶어 7개만 있다.
    - 회사 이름 줄에 `프로젝트 50개+` 로 적는다. 목록 위에 두던 「대표 프로젝트 N개만 적었습니다.」 는 뺐다.(2026-11-16 사용자 결정)
    - 정확히 세지 못한 최소치라 `+` 를 붙인다.(`totalProjects`)
- **2014년 이후에 시작한 회사(KOCOM · NEWEN AI)는 프로젝트 목록을 처음부터 펼친다.** 프로젝트 11개다.
- **그 이전의 회사 4곳은 접어 둔다.** 회사 이름 · 기간 · 프로젝트 수만 보이고, 누르면 목록이 펼쳐진다.
- 요약은 회사 이름 줄 바로 아래에 작게 적고, 회사를 펼쳤을 때만 보인다.(2026-11-16 사용자 결정) 글자색은 `muted-foreground` 다.
    - 목록과 같은 속도로 높이가 늘어나며 나타난다. 갑자기 생기면 제목 줄의 높이가 튄다.
- 요약을 쓰지 않은 회사는 요약 줄을 그리지 않는다. 지금은 6곳 모두 초안 문구가 들어 있다.
- 작업 상세가 있는 프로젝트는 이름이 `/work/<slug>` 링크다. 지금은 `KOZIPSA Web Admin` 하나다.
- 기술 태그 표기는 하나로 맞췄다. `MarkUp` → `Markup`, `Design Stytem` → `Design System`, `Paas` → `PaaS` 다.
- 기존 페이지의 전화번호와 Gmail 주소는 옮기지 않는다. 연락은 홈과 같은 메일 버튼 하나다.([home/](../home/README.md) 요구사항 6)
- **제목 줄 오른쪽에 「전체 펼치기」 버튼을 둔다.** 누르면 회사 6곳을 모두 펼치고 문구가 「전체 닫기」 로 바뀐다. 다시 누르면 모두 닫는다.(2026-11-16 사용자 결정)
    - 회사를 하나씩 여닫아 모두 펼쳐진 상태가 되면 문구도 「전체 닫기」 로 바뀐다.(`src/features/experienceTimeline/ui/ExperienceToggleAll.tsx`)
- 회사는 모두 `details` 로 여닫는다. 스크립트 없이 열리고 키보드로도 열린다. 펼쳐 둔 회사도 접을 수 있다.

| 요소               | 계기            | 연출                                      | 도구          | 토큰                           | 동작 줄이기    |
| ------------------ | --------------- | ----------------------------------------- | ------------- | ------------------------------ | -------------- |

| 회사 화살표        | 여닫음          | 화살표가 뒤집힌다                         | CSS           | `duration-fast` · `ease-move`  | 바로 뒤집힘    |
| 프로젝트 목록      | 여닫음          | 높이가 0 과 제 높이 사이를 오간다         | CSS           | `duration-base` · `ease-move`  | 바로 여닫힘    |
| 회사 요약          | 여닫음          | 높이가 0 과 제 높이 사이를 오간다         | CSS           | `duration-base` · `ease-move`  | 바로 나타남    |
| 제목 밑줄          | 화면에 들어옴   | 선으로 그려진다                           | framer-motion | `DURATION.slow` · `EASE.enter` | 다 그려진 상태 |

- 경력 항목이 하나씩 올라오는 연출은 넣지 않았다. 접힌 회사를 펼칠 때마다 다시 실행돼 읽기를 방해한다.
- **프로젝트 목록과 회사 요약은 높이가 늘어나고 줄어들며 여닫힌다.**(2026-11-16 사용자 결정) 높이를 움직이는 것은 `docs/motion.md` 원칙 4 의 예외다. 뚝 끊기는 전환을 피하려고 정했다.
    - `interpolate-size` 를 지원하지 않는 브라우저에서는 움직이지 않고 바로 여닫힌다.(`src/features/experienceTimeline/ui/ExperienceTimeline.tsx`)

## 데이터

경력 원문은 `content/experiences.json` 이고, 읽는 곳은 entity `experience` 다.(`src/entities/experience/`)
기존 소개 페이지에서 옮긴 임시 데이터다.(요구사항 6) `src/app/about/page.tsx` 가 읽어 타임라인에 넘긴다.

| 단위     | 항목            | 내용                                                                         |
| -------- | --------------- | ---------------------------------------------------------------------------- |
| 회사     | `slug`          | 구분 값                                                                      |
| 회사     | `company`       | 회사 이름                                                                    |
| 회사     | `startYear`     | 들어간 해                                                                    |
| 회사     | `endYear`       | 떠난 해. 재직 중이면 `null`                                                  |
| 회사     | `summary`       | 역할과 한 일 한두 줄. 지금은 프로젝트 목록을 보고 쓴 초안이다                |
| 회사     | `totalProjects` | 실제로 한 프로젝트 수. 목록에 대표만 적은 회사에 준다. 지금은 NEWEN AI 의 50 |
| 프로젝트 | `name`          | 프로젝트 이름                                                                |
| 프로젝트 | `date`          | 한 시기. `2025.06` 또는 `2022`                                               |
| 프로젝트 | `tags`          | 쓴 기술과 맡은 일                                                            |
| 프로젝트 | `workSlug`      | 작업 상세가 있으면 그 slug                                                   |

화면용 가공은 `services` 가 한다. 기간 문구(`2025 – 현재`), 처음부터 펼칠지, 작업 상세 주소를 만든다.

나머지 문구는 저장소에 두고 entity `about` 이 읽는다.(`src/entities/about/`) `src/app/about/page.tsx` 가 읽어 섹션마다 넘긴다.
관리 화면의 소개(`/admin/about`)에서 고친다.([소개 관리 기획](../admin/about/README.md))

| -------------------- | ------------------- | ------------------------------- |

## 접근성 · 성능 고려

- 타임라인은 `ol` 이다. 순서에 의미가 있다. 회사 안의 프로젝트 목록도 `ol` 이다.
- 접힌 회사에는 프로젝트 수를 글자로 적는다. 펼치지 않아도 양을 알 수 있다.
- 56개를 한 번에 그리면 화면이 길어진다. 접어 두는 것이 길이를 줄이는 방법이다.
- 큰 캐릭터 이미지는 화면 폭에 맞는 크기로 내린다.
