# 작업 목록 · 상세 (`/work`) — 기획

포트폴리오에 실은 작업을 모아 보고, 작업 하나를 케이스 스터디로 읽는 페이지다.

**초안이다.** 사용자가 아직 채택하지 않은 페이지를 제안으로 채운 문서다.(`../README.md` 3.2)
모든 기획안이 `제안` 이고, 채택하면 [검토 필요 사항](#검토-필요-사항)에서 하나씩 확정한다.

아직 없다. 홈 기획의 검토 필요 사항 3번(작업 목록 · 상세 연결)이 이 페이지를 가리킨다.([home/](../home/README.md))

## 정책(제안)

### 목록

- 카드는 홈과 같은 `ProjectCard` 를 쓴다. 같은 작업이 2곳에서 다르게 보이지 않게 하기 위해서다.
- 위에 분류 필터를 둔다. `전체` 와 작업에 있는 분류만 보인다. 분류는 작업의 `category` 값에서 만든다.
- 고른 필터는 주소에 남긴다(`/work?category=Dashboard`). 주소를 넘기면 같은 목록이 열린다.
- 순서는 관리 화면에서 정한 순서다. 정렬 선택은 두지 않는다. 작업이 많지 않다.

### 상세

- 본문은 Markdown 이다. 관리 화면에서 쓰고 저장소에 둔다.([admin/](../admin/README.md))
- 절은 개요 · 문제 · 해결 · 결과 · 회고 순서다. 결과에는 가능하면 숫자를 쓴다.
- 머리에 메타를 둔다. 역할 · 기간 · 기술 · 외부 링크(서비스 · 저장소)다. 없는 항목은 감춘다.
- 아래에 이전 · 다음 작업을 둔다. 관리 화면에서 정한 순서를 따른다.
- 없는 `id` 로 들어오면 404 다.([not-found/](../not-found/README.md))
- 빌드할 때 모든 상세를 미리 만든다(`generateStaticParams`).

## 데이터(제안)

작업 원문은 관리 기능의 저장소로 옮긴다.([admin/](../admin/README.md) 「데이터」) 지금의 항목에 아래 항목을 더하고, 본문에 케이스 스터디를 쓴다.
아래 항목을 언제 더할지는 정하지 않았다.(2026-11-12 사용자 결정, 관리 기획 요구사항 5)

| 항목                                       | 지금 | 더할 것                                                                      |
| ------------------------------------------ | ---- | ---------------------------------------------------------------------------- |
| `slug`                                     | 있다 | `id` 로 바뀐다. 저장소가 발급한다.([admin/](../admin/README.md) 요구사항 10) |
| `title` · `category` · `summary` · `image` | 있다 | —                                                                            |
| `role`                                     | 없다 | 맡은 일                                                                      |
| `period`                                   | 없다 | 기간. 표시는 `2025.03 – 2026.01`                                             |
| `stack`                                    | 없다 | 기술 목록                                                                    |
| `links`                                    | 없다 | 서비스 · 저장소 주소                                                         |
| 본문                                       | 없다 | Markdown                                                                     |

`entities/project` 의 스키마에 위 항목이 더해지고, services 의 `ProjectData` 에도 더해진다.

## 접근성 · 성능 고려

- 필터는 버튼 묶음이고, 고른 버튼에 `aria-pressed="true"` 를 단다.
- 상세 제목은 `h1`, 본문 절은 `h2` 다.
- 상세 이미지는 `next/image` 로 그리고 본문 폭에 맞춰 크기를 정한다.
