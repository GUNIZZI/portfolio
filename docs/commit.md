# 커밋

Kozipsa(`admin-next/docs/commit.md`)의 형식과 커밋 게이트를 그대로 가져왔다.(2026-11-11 사용자 결정)
영역 체계만 이 사이트에 맞게 바꿨다.

커밋 메시지는 **나중에 이 코드를 다시 보는 사람이 읽는 설명**이다.

## 원칙

1. **커밋 하나에 관심사 하나만 담는다.** type 이 2개 필요하면 커밋을 2개로 나눈다.
2. **제목은 무엇을 했는지, 본문은 왜 했는지 쓴다.** 파일 목록은 `git show` 로 볼 수 있다.
3. **영역은 사람이 부르는 이름으로 쓴다.** 폴더 경로가 아니라 화면·섹션 이름이다.
4. **type 은 7개만 쓴다.** 새로 만들지 않는다.

## 형식

```
[<type>] <영역 > 하위영역> - <변경 요약>

- 세부 변경점
- 세부 변경점
```

제목은 72자 이내이고 마침표로 끝내지 않는다. 요약은 명사형으로 끝낸다(`~수정`, `~추가`).
영역 구분자는 `>` 하나다. 대괄호는 type 표기 전용이다.

### type 7개

| type       | 용도                            |
| ---------- | ------------------------------- |
| `feat`     | 기능 추가                       |
| `fix`      | 버그 수정                       |
| `refactor` | 동작 변화 없는 구조·네이밍 개선 |
| `style`    | UI/CSS, 코드 포맷팅             |
| `docs`     | 문서                            |
| `chore`    | 의존성, 설정, gitignore, 빌드   |
| `test`     | 테스트 코드                     |

### 영역

| 대상          | 표기                                                 |
| ------------- | ---------------------------------------------------- |
| 페이지·섹션   | `홈 > 히어로`, `홈 > 대표 작업`, `작업 상세`, `소개` |
| 전역 위젯     | `공통 > 헤더`, `공통 > 커서`, `공통 > 페이지 전환`   |
| 디자인 시스템 | `DS > 토큰`, `DS > 컴포넌트 > Reveal`, `DS > 모션`   |
| 콘텐츠        | `콘텐츠 > <프로젝트 이름>`                           |
| 도메인 무관   | `구조`, `의존성`, `빌드`, `문서`, `AX`               |

`AX` 는 `.claude/` 와 `CLAUDE.md` 변경이다.

## 디자인 시스템 커밋

`src/style/tokens/` 와 `src/shared/ui/` 를 고친 커밋에는 **문서가 함께 있어야 한다.**
`.claude/hooks/guard-commit.py` 의 `DS_PREFIXES` 가 이 2곳을 검사하고, 문서 없이 스테이징하면 차단한다.(Kozipsa 에서 가져옴)
문서가 필요 없다면 그 근거로 컨펌을 받고 `.git/.commit-docs-ok` 를 발급한다.

| 고친 곳                                    | 대조할 문서             |
| ------------------------------------------ | ----------------------- |
| `src/style/tokens/color.css` · `layer.css` | `docs/theme.md`         |
| `src/style/tokens/motion.*`                | `docs/motion.md`        |
| `src/shared/ui/<Name>/`                    | 같은 폴더의 `<Name>.md` |

## 커밋하는 법

**커밋은 커밋 스킬로만 한다.** 평문 "커밋해줘" 에는 스킬을 호출하라고 한 줄로 안내만 한다.

| 스킬            | 상황                                                     |
| --------------- | -------------------------------------------------------- |
| `/commit`       | 디자인 시스템을 건드렸거나, 규칙·상수·경로가 바뀌었을 때 |
| `/commit-quick` | 그 밖. 문서 점검을 생략한다                              |

`git commit` 은 PreToolUse 훅이 막고, 스킬 절차의 1회용 토큰이 있을 때만 통과한다.
husky `pre-commit` 이 lint-staged 와 `tsc` 를 돌린다.

**Co-Authored-By 등 생성 도구 서명을 붙이지 않는다.**(Kozipsa `/commit` 스킬 5단계)

템플릿은 루트 `.gitmessage` 다. clone 후 1회: `git config commit.template .gitmessage`

## 금지사항

| 금지                                | 대신                       | 근거                                                   |
| ----------------------------------- | -------------------------- | ------------------------------------------------------ |
| `feat: 히어로 수정`                 | `[feat] 홈 > 히어로 - …`   | 대괄호 접두가 없으면 grep 으로 걸러낼 수 없다(Kozipsa) |
| `홈 -> 히어로` · `홈/히어로`        | `홈 > 히어로`              | 구분자가 섞이면 영역별로 이력을 모을 수 없다(Kozipsa)  |
| `src/features/hero 수정`            | `홈 > 히어로`              | 폴더 경로만으로는 어느 화면인지 알 수 없다(Kozipsa)    |
| 기능 추가와 리팩터링을 한 커밋에    | 커밋 2개로                 | 되돌릴 때 원하는 쪽만 떼어낼 수 없다(Kozipsa)          |
| `.env` · `.mcp.json` · `*.pem` 포함 | 제외하고 `.gitignore` 보완 | 자격증명은 지운 뒤에도 이력에 남는다(Kozipsa)          |

## 미정리 항목

- 이력이 없다. 첫 커밋부터 이 형식을 따른다.

## 확인방법

```zsh
# type 접두 위반. 기대: 출력 없음
git log --pretty=%s -100 | grep -vE '^\[(feat|fix|refactor|style|docs|chore|test)\] '

# 제목 72자 초과. 기대: 출력 없음
git log --pretty=%s -100 | python3 -c "import sys; [print(l) for l in sys.stdin.read().splitlines() if len(l) > 72]"
```
